# 스토어 신고 답안 초안

Play Console 과 App Store Connect 에 옮겨 넣을 답이다. 스토어 계정에서 넣는 일과 시연 영상 촬영은 사람이 한다. 판단이 갈리는 답은 "정할 것"으로 표시했다. 근거가 되는 앱 동작은 `docs/privacy-policy.md` 와 같다.

공통으로 넣는 값:

- 개인정보처리방침 주소: `https://github.com/nosorae/malhaebom-opic/blob/main/docs/privacy-policy.md` (앱 설정 화면의 링크와 같다. 저장소가 공개돼야 열린다)
- 대상 연령: 만 18세 이상 (Gemini API 이용 조건)

## 1. Google Play Data safety

이 절의 답은 `fastlane/data-safety.csv` 에 그대로 들어 있다. Play Console 의 데이터 보안 페이지에서 "CSV 가져오기"로 올리면 칸이 채워진다. 가져오면 이미 넣은 답을 덮어쓴다. 파일은 콘솔이 내보내는 양식의 행과 열을 그대로 두고 답 칸만 채웠다. `python3 -m unittest scripts/test_data_safety.py` 가 양식과 답을 확인한다.

| 질문 | 답 |
|---|---|
| 필수 데이터 유형 중 수집하거나 공유하는 것이 있나 | 예 |
| 전송 중 암호화하나 | 예. Gemini 요청은 HTTPS 만 쓰고, 네트워크 보안 설정이 평문 통신을 막는다 |
| 사용자가 데이터 삭제를 요청할 수 있나 | 아니요. 앱을 만든 쪽은 데이터를 보관하지 않아 요청받을 곳이 없다. 기기 안 데이터는 앱 삭제로, 키는 설정에서 지운다 |

데이터 유형별 답:

| 유형 | 수집 | 공유 | 처리 | 필수 여부 | 목적 |
|---|---|---|---|---|---|
| 오디오 > 음성 또는 소리 녹음 | 예 | 예(Google, Gemini API) | 일시 처리 아님. 무료 등급은 Google 이 제품 개선에 쓸 수 있다 | 필수(답변 분석이 앱의 기능이다) | 앱 기능 |

신고하지 않는 것과 이유:

- 답변 전문, 피드백, 점수: Gemini 가 돌려준 결과를 기기에만 둔다. 기기 밖으로 다시 나가지 않는다
- API 키: 사용자가 Google 에서 받은 인증 값이다. Google 에 인증용으로만 보내고 앱을 만든 쪽은 받지 않는다
- 기기 식별자, 위치, 앱 활동, 오류 기록: 읽지 않고 보내지 않는다. 분석, 광고, 오류 보고 라이브러리가 없다

정할 것(#156): 사용자가 자기 키로 Google 에 직접 보내는 녹음을 "공유"로 볼지. CSV 에서 이 판단에 걸린 줄은 `PSL_DATA_USAGE_ONLY_SHARED` 와 `DATA_USAGE_SHARING_PURPOSE` 의 `PSL_APP_FUNCTIONALITY` 두 줄이고 지금은 초안대로 TRUE 다. 공유가 아니라고 정하면 두 줄을 비운다. 앱을 만든 쪽 대신 처리하는 서비스 제공자가 아니고 사용자가 계약한 제3자라서 위 표는 공유로 답했다. 신고를 넓게 하는 쪽이 심사에서 덜 위험하다.

## 2. Google Play 포그라운드 서비스 신고

앱은 포그라운드 서비스 두 가지를 쓴다. 콘솔에서 유형마다 따로 신고한다.

### 2.1 녹음

| 항목 | 답 |
|---|---|
| 서비스 유형 | `microphone` (`FOREGROUND_SERVICE_MICROPHONE`) |
| 서비스 | `RecordingService` (libs/recorder) |
| 사용 사례 | 기타. 사용자가 시작한 음성 녹음 |

용도 설명 (콘솔에 넣는 문구):

> 사용자는 영어 말하기 시험 문항마다 답을 말하고 앱이 그 답을 녹음한다. 녹음은 질문 재생이 끝나면 사용자가 연 문항 화면에서 시작되고, 사용자가 다음 문항으로 넘어가거나 시험을 나가면 끝난다. 답하는 도중 화면이 꺼지거나 사용자가 잠시 다른 앱으로 가도 답변이 끊기면 안 되므로 마이크 포그라운드 서비스로 녹음을 잇는다. 서비스가 도는 동안 "답변을 녹음하는 중" 알림이 계속 보인다. 앱이 화면에 없을 때 새 녹음을 시작하지 않는다.

시연 영상(사람이 찍는다): 모의고사 시작, 문항 Play, 녹음 시작과 알림 표시, 화면 끄기 또는 홈으로 가기, 돌아와서 다음 문항으로 넘기면 알림이 사라지는 장면까지 한 번에 찍는다. 길이는 1분 안쪽으로 한다.

### 2.2 답변 분석 전송

| 항목 | 답 |
|---|---|
| 서비스 유형 | `dataSync` (`FOREGROUND_SERVICE_DATA_SYNC`) |
| 서비스 | WorkManager 의 `SystemForegroundService` (libs/work-queue 의 분석 비우기 작업이 `setForeground` 로 띄운다) |
| 사용 사례 | 네트워크 전송. 사용자가 녹음한 답변을 사용자의 Gemini 키로 보내고 분석 결과를 받아 기기에 저장한다 |

용도 설명 (콘솔에 넣는 문구):

> 사용자가 문항에 답하면 앱은 그 녹음을 사용자가 넣은 Gemini API 키로 보내 문법 교정과 등급을 받는다. 모의고사 한 회차는 15개 답변과 등급 요청이라 몇 분이 걸린다. 사용자가 기다리는 동안 다른 앱으로 가도 보내던 요청이 끊기지 않게 데이터 동기화 포그라운드 서비스로 전송을 잇는다. 서비스가 도는 동안 "답변을 분석하고 있어요" 알림에 몇 개 중 몇 개가 끝났는지 보이고, 보낼 것이 다 끝나면 서비스와 알림이 바로 내려간다. 사용자가 녹음하지 않은 데이터는 보내지 않는다.

시연 영상(사람이 찍는다): 연습 문항 하나 또는 모의고사 몇 문항에 답하고, 분석이 시작되면 홈으로 간다. 알림창에 진행 알림이 보이고, 분석이 끝나면 진행 알림이 사라지고 "리포트가 준비됐어요" 알림이 뜨고, 그 알림을 누르면 리포트가 열리는 장면까지 한 번에 찍는다.

### 2.3 알림 권한 (Android 13 이상, iOS)

- 첫 분석을 시작할 때 한 번 묻는다. 진행 알림(Android)과 "리포트가 준비됐어요", 분석 실패 알림에만 쓴다. 광고나 홍보 알림은 없다
- 거절해도 분석은 그대로 돌고, 결과는 앱을 열면 리포트에서 본다. 다시 묻지 않는다
- Play Console 에는 따로 신고할 칸이 없다. App Store 심사 메모에 위 용도를 한 줄 적는다
- iOS 26 이상은 분석 진행을 시스템 진행 표시(잠금화면, 다이내믹 아일랜드)에 띄운다(`BGContinuedProcessingTask`). 사용자가 거기서 멈추면 남은 분석을 취소로 남긴다. 따로 신고할 항목은 없다

## 3. App Store App Privacy

| 항목 | 답 |
|---|---|
| 데이터를 수집하나 | 예 |
| 유형 | 오디오 데이터 (Audio Data) |
| 목적 | 앱 기능 (App Functionality) |
| 사용자 신원과 연결 | 아니요. 앱은 계정이 없고 녹음에 신원 정보를 붙이지 않는다 |
| 추적에 쓰나 | 아니요 |

정할 것: 무료 등급 키로 보낸 녹음은 Google 이 요청 처리 뒤에도 보관할 수 있어 "수집"으로 답했다. 유료 키만 쓰는 사용자에게는 해당하지 않지만 앱이 등급을 고르지 않으므로 넓게 신고한다.

## 4. 심사 메모 (두 스토어 공통)

> 이 앱은 서버가 없다. 사용자가 자기 Google Gemini API 키를 넣고, 앱이 그 키로 Gemini 에 답변 녹음을 보내 분석한다. 녹음을 보내기 전에 전송 동의 화면을 보여 주고 동의 버튼을 눌러야 보낸다. 심사용 키는 심사 정보의 메모 칸에 따로 넣는다.

App Store 에 올리는 메모 전문은 `metadata/ios/review_information/notes.txt` 다. 심사용 키는 저장소에 두지 않고, 올릴 때 환경 변수 `REVIEW_GEMINI_KEY` 로 넘기거나 사람이 콘솔의 심사 정보 칸에 직접 넣는다.

## 5. 스토어에 올리기 전에 남은 것

- 저장소를 공개해 개인정보처리방침 주소가 열리게 한다
- Play Console: Data safety, 포그라운드 서비스 신고(녹음, 답변 분석 전송)와 시연 영상 두 개, 대상 연령, 콘텐츠 등급 설문
- App Store Connect: App Privacy, 심사 메모와 심사용 키
- iOS 앱의 `Info.plist` 에 아직 마이크 사용 문구(`NSMicrophoneUsageDescription`)와 백그라운드 오디오(`UIBackgroundModes` 의 `audio`)가 없다. iOS 녹음을 앱에 연결할 때 넣어야 심사를 통과한다
- 녹음 저장소는 `filesDir/recordings/` 아래에 써야 Android 백업 제외 규칙(`res/xml/data_extraction_rules.xml`)이 맞는다. iOS 는 녹음 폴더에 백업 제외 속성을 붙여야 한다
- 릴리스 서명 키와 업로드 키 준비
