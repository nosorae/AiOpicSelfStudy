# 제품 요구사항

실제 오픽 한 회를 그대로 체험하는 모의시험과, 질문 하나만 푸는 한 문항 연습을 주는 앱이다. 답변마다 AI 피드백이 쌓이고, 모의시험은 예상 등급 범위가 나온다. 모의시험은 앱을 껐다 켜도 이어서 풀 수 있어 틈새 시간에 나눠 본다. Compose Multiplatform 으로 Android, iOS 를 같이 만들고 오픈소스로 공개한다.

설계는 `design.md`, 설계 결정은 `../adr/` 에 있다.

## 1. 목표

오픽 AL 을 목표로 하는 사용자가 실제 시험과 같은 조건에서 연습하고, 답변마다 무엇을 고칠지 안다.

## 2. 범위

넣는 것: 모의시험 15문항, 이어 보기, 한 문항 연습, 답변별 피드백, 회차 예상 등급, 회차별 기록, 약점 출제, 틀린 교정 표시, 분석 모델 고르기.

첫 버전의 AI 제공사는 Gemini 하나다. 분석 구조는 음성을 못 듣는 제공사(Claude, OpenAI 텍스트 모델)도 붙일 수 있게 나눠 둔다(F5.9). 그 제공사들의 실제 연결은 다음 버전에서 한다.

| 뺀 것 | 이유 |
|---|---|
| 서버, 계정 | 사용자가 자기 AI 제공사 키(첫 버전은 Gemini)를 쓴다 |
| Claude, OpenAI 실제 연결 | 첫 버전은 구조만 열어 둔다. 음성을 못 듣는 제공사의 두 단계 경로는 가짜 제공사 테스트로만 확인한다 |
| 정한 시각에 울리는 전화 | 알람 권한, 꽉 찬 화면 권한, 재부팅 재등록, iOS AlarmKit 처리가 따라붙는데 연습의 핵심이 아니다 |
| 3문항 짧은 회차 | 한 문항 연습이 그 역할을 한다 |
| 채점 정확도 측정, 직접 채점 정답지 | 정답 등급을 얻으려면 실제 시험을 보거나 직접 채점해야 한다. 틀린 교정 표시가 쌓이면 나중에 정답지로 쓴다 |

## 3. 사용자 흐름

**처음 실행.** 시스템 스플래시가 떠 있는 동안 앱이 키와 동의 상태를 읽고 갈 곳을 정한다. 키가 없으면 키 입력 화면에 머문다. 키 입력 화면은 제공사를 고르고 키를 넣는 구조인데 첫 버전에는 Gemini 만 보인다. 키를 넣은 뒤 녹음한 음성이 Google Gemini 로 간다는 안내에 동의해야 홈으로 간다. 두 플랫폼 모두 같다.

**모의시험.** 서베이(지난 선택으로 채워져 있음), 수준 선택(1~6), 마이크 점검과 연습 문항, 1~7번, 난이도 재조정, 8~15번 순으로 간다. 끝나면 리포트가 나온다. 중간에 앱을 꺼도 다시 켜면 멈춘 문항에서 이어진다.

**한 문항 연습.** 홈에서 "한 문항 풀기"를 누르면 약점 유형에서 질문 하나가 나오고, 답하면 바로 피드백이 나온다.

**리포트와 기록.** 답변마다 전문, 교정, 한 등급 위 표현, 시제와 문단 길이와 속도와 멈춤을 본다. 모의시험은 예상 등급 범위와 근거가 붙는다. 기록 화면은 회차별 예상 등급 변화와 한 문항 연습 답변을 함께 보여 준다. 리포트와 기록에는 어느 모델이 분석했는지가 보인다.

**모델 고르기.** 설정에서 분석 모델을 고른다. 처음에는 안정(Stable) 모델이 골라져 있다. 미리보기 모델을 고르면 2주 공지로 내려갈 수 있다고 안내한다.

### 화면 목록

앱을 켜면 시스템 스플래시가 떠 있는 동안 갈 곳을 정한다(S0, 그리는 화면이 아니다). 이동은 아래 탭 셋(홈, 기록, 설정)이 기본이다. 하위 화면의 탭 표시는 플랫폼마다 다르다. Android 는 최상위 탭 화면(홈, 기록, 설정)에서만 탭을 보이고 하위 화면에서는 숨긴다. iOS 는 리포트 상세 같은 하위 화면에도 탭을 남긴다. 모의시험에 들어가면 두 플랫폼 모두 탭이 사라지고(시험 진행과 녹음은 전체 화면) 앞으로만 간다. 시험 중 "나가기"는 저장하고 홈으로 돌아가고, 홈에서 이어 본다.

| S1 | 키 입력 (키가 없을 때). 제공사 선택 + 키 입력 구조, 첫 버전은 Gemini 하나만 보인다. 맨 위 안내 카드가 왜 내 키가 필요한지 알린다(서버가 없어 내 키로 내 녹음을 Gemini 에 바로 보내고, 요금과 사용량은 내 Google 계정에 잡힌다). 키 받는 순서 세 단계(만들기, 복사, 붙여 넣기)와 "Gemini 키 받기" 버튼이 있고, 버튼은 시스템 브라우저로 제공사의 키 발급 페이지를 연다. 입력란은 키를 가리지 않고 고정폭 글자로 보이며, 글자가 있으면 칸 안 오른쪽에 지우기 버튼이 있다. 입력란 아래에 "키는 이 기기에만 암호화해서 저장하고, Gemini 에 요청할 때 말고는 어디에도 보내지 않습니다." 를 둔다. 확인하는 동안 저장 버튼은 진행 표시를 보이고 다른 입력은 막는다 | F1.1, F1.2 |

## 4. 기능 요구사항

각 항목이 수락 기준이다. 테스트로 확인할 수 있게 쓰고, 이슈와 테스트가 이 번호를 가리킨다.

### F1. 첫 실행

- F1.0 앱은 시스템 스플래시(Android SplashScreen API 의 `setKeepOnScreenCondition`, iOS 실행 화면)를 잡아 둔 채 저장된 상태만 읽고, 키가 없으면 S1, 동의 전이면 S2, 둘 다 되어 있으면 홈으로 보낸다. 스플래시를 따로 그리지 않는다. 키 확인 요청은 여기서 보내지 않는다
- F1.1 제공사를 고르고 키를 넣으면 그 제공사에 짧은 요청을 보내 키가 맞는지 확인한다. 틀리면 이유를 보여 주고 저장하지 않는다. 첫 버전의 제공사 목록에는 Gemini 하나만 보인다. 키 입력 화면에서 시스템 브라우저로 제공사의 키 발급 페이지(Gemini 는 https://aistudio.google.com/apikey)를 열 수 있다. 키는 가리지 않고 보이며 지우기 버튼으로 비울 수 있다. 확인 전에 붙여 넣으며 딸려 온 글자를 뺀다. 공백과 줄바꿈, 마크다운 이스케이프 역슬래시, 눈에 안 보이는 문자(U+200B~U+200D, U+2060, U+FEFF)다. 키 글자(영문, 숫자, `.`, `-`, `_`)는 그대로 둔다.
- F1.2 키는 제공사마다 따로 저장하고 제공사 이름으로 구분한다. Android 에서 Keystore AES-GCM 키로 암호화해 DataStore 에, iOS 에서 Keychain(`AfterFirstUnlockThisDeviceOnly`)에 둔다. 한 제공사 키를 지워도 다른 제공사 키는 남는다
- F1.3 두 플랫폼 모두 동의 전에는 어떤 녹음도 전송하지 않는다. 동의는 사용자가 버튼을 눌러야 성립하고, 뒤로가기나 홈으로 나가는 것은 동의가 아니다. 동의 화면은 마이크 권한 요청(S6)보다 먼저 나온다. 설정에서 동의를 철회하면 대기 중인 전송도 멈추고 다음 실행 때 S2 로 간다. 동의 화면은 Gemini 무료 등급으로 보낸 음성이 Google 제품 개선에 쓰일 수 있다고 알린다. 키 입력 화면과 모델 선택 화면은 이 안내로 연결만 한다

### F2. 모의시험 진행

- F2.1 화면 순서는 서베이, 수준 선택, 점검, 연습 문항, 1~7번, 재조정, 8~15번, 끝이다. 수준 1~2 는 12문항이다
- F2.2 서베이 Part 4 는 네 묶음마다 최소 개수(2, 1, 1, 1)를 채우고 합쳐서 12개 이상이어야 다음으로 간다. 지난 선택(설정에서 바꾼 답 포함)을 미리 채운다
- F2.3 문항 화면에 질문 글자는 없다. Play 를 누르면 질문을 기기 음성으로 읽고 끝나면 녹음이 저절로 시작된다
- F2.4 녹음 시작 5초 안에만 다시 듣기 한 번. Next 는 녹음 10초 뒤에 켜진다. 지나간 문항으로 못 간다
- F2.5 40분 타이머는 1번에서 시작하고 문항 화면을 벗어나 있는 동안(나가기, 앱 종료) 멈춘다. 기기 시각을 바꿔도 흔들리지 않는다
- F2.6 40분이 지나면 답한 문항까지만 채점하고 남은 문항은 "시간 부족"으로 표시한다
- F2.7 문항별 답변 타이머는 기본으로 끄고 설정에서 켠다

### F3. 이어 보기

- F3.1 진행은 공통 코드의 순수 함수 하나가 계산한다. 상태가 바뀔 때마다 통째로 저장한다
- F3.2 녹음은 몇 초 단위 조각 파일로 바로 쓴다. 앱이 죽으면 쓰던 조각 하나만 잃는다
- F3.3 다시 켜면 같은 문항에서 이어 녹음한다. 그 문항에서 다시 듣기를 안 썼으면 한 번 들을 수 있다
- F3.4 진짜 전화나 Siri 가 끼어들면 그 구간을 표시하고, 끝나면 새 조각으로 다시 녹음한다
- F3.5 화면이 꺼지거나 다른 앱으로 가도 녹음은 이어진다(Android 마이크 서비스, iOS 백그라운드 오디오)

### F4. 한 문항 연습

- F4.1 홈에서 언제든 시작한다. 질문 하나, 모의시험과 같은 문항 규칙
- F4.2 답하면 피드백을 바로 보여 준다

### F5. AI 분석

- F5.1 Next 를 누르면 그 답변을 바로 분석 대기열에 넣는다. 15개를 한꺼번에 보내지 않고 순서대로 보낸다
- F5.2 답변 피드백: 전문, 교정(원문 구절과 고친 문장), 한 등급 위 표현, 시제 유지, 문단 길이, 말 속도, 멈춘 시간, 롤플레이에서 한 질문 수
- F5.3 회차 등급: 15번이 끝나면 답변 피드백과 녹음을 묶어 한 번 보낸다. ACTFL 기준 문장을 예/아니오 체크리스트로 채우고, 체크 결과로 등급 범위(예: IH ~ AL)와 근거를 정한다
- F5.4 앱 코드 검사: 교정의 원문 구절이 전문에 있어야 한다. 값 범위, 문항 수, 주제를 확인한다. 통과 못하면 한 번 다시 요청하고 그래도 안 되면 그 항목을 버린다
- F5.5 무음, 한국어, 5초 미만 녹음이면 이유 코드를 돌려받고 "평가할 수 없음"으로 보여 준다
- F5.6 오프라인이면 녹음은 그대로 하고 분석은 대기열에 둔다. 429, 408, 5xx 만 지수 백오프로 최대 3회 재시도한다. 실패해도 녹음은 남는다
- F5.7 기본 모델은 앱이 정한 안정 모델 하나로 고정한다. 사용자가 바꾸면 그 모델을 쓴다. 답변 결과마다 `provider`, `model`(모델 id), `promptVersion` 을 저장하고 리포트와 기록에 보여 준다. 한 회차 안에서 답변 분석 모델이 섞이면 회차 등급 옆에 표시한다
- F5.8 설정에서 분석 모델을 고른다. 목록은 앱이 들고 있는 검증된 목록이다. 항목마다 모델 id, 표시 이름, 음성 직접 분석 가능 여부, 안정 또는 미리보기를 둔다. 제공사 모델 목록 API 로는 오디오 지원 여부를 알 수 없고, 출력 검사(F5.4)를 모델마다 확인해야 해서다. 미리보기 모델을 고르면 2주 공지로 내려갈 수 있다고 안내한다. 고른 모델이 내려가 요청이 실패하면 기본 모델로 돌리고 사용자에게 알린다
- F5.9 분석은 두 단계로 나눌 수 있게 만든다. 받아쓰기(전문과 단어 시각)와 글 분석(교정, 표현, 체크리스트, 등급)이다. 음성을 직접 듣는 모델(Gemini)은 두 단계를 한 번 호출로 처리한다. 음성을 못 듣는 제공사는 기기 음성 인식이나 다른 제공사로 받아쓴 뒤 글만 보내고, 발음 항목은 "평가 안 함"으로 표시한다. 첫 버전은 이 경로를 테스트 안의 가짜 제공사로만 끝까지 돌린다

### F6. 출제

- F6.1 Gemini 가 서베이 주제, 수준, 재조정 선택, 약점 점수를 받아 문항 유형 순서에 맞춰 질문을 만든다
- F6.2 생성이 실패하면 앱에 넣어 둔 문항 풀에서 서베이 주제로 고른다. 내장 문항은 직접 쓴다. 기출 원문은 넣지 않는다
- F6.3 사용자는 자기 문항 파일(JSON)을 불러올 수 있다

### F7. 리포트와 기록

- F7.1 답변 리포트: F5.2 의 항목. 한 문항 연습과 모의시험 답변이 같은 화면을 쓴다
- F7.2 회차 리포트: 등급 범위, 근거, 어느 문항에서 무너졌는지, 15개 답변 목록
- F7.3 기록: 회차별 예상 등급 변화, 문항 유형별 약점
- F7.4 기록 목록에 모의시험 회차와 한 문항 연습 답변(한 문항이 한 줄)을 저장한 순서로 섞어 최근 것부터 보인다. 회차는 등급, 연습은 문항 유형과 점수를 보이고, 분석 중과 분석 실패도 그 줄에 보인다. 연습 줄을 누르면 그 답변 리포트가 열린다. 두 종류가 다 있으면 전체, 모의시험, 연습으로 거른다

### F8. 틀린 교정 표시

- F8.1 교정 항목마다 "틀림"을 누를 수 있다
- F8.2 틀림으로 표시한 교정은 약점 점수 계산에서 뺀다
- F8.3 표시한 교정은 원래 답변 전문, 교정 내용, `provider`, `model`, `promptVersion` 과 함께 기기에 남는다. 설정에서 JSON 으로 내보낼 수 있다. 서버가 없으니 사용자가 원하면 저장소 이슈에 붙인다
- F8.4 쌓인 표시는 프롬프트를 고칠 때 오류 분석 재료로 쓴다(`docs/error-analysis.md`)

### F9. 화면 모드

- F9.1 설정에서 화면 모드를 "시스템 따라가기", "라이트", "다크" 중에서 고른다. 기본값은 시스템 따라가기다. 두 플랫폼이 같은 화면을 쓴다. Android 9 기기는 시스템 다크 설정이 없어서 앱 안 선택이 없으면 다크를 쓸 수 없다

### 디자인 시스템

Montage(MIT, v4.0.0 태그 고정)의 토큰과 컴포넌트를 Compose 공통 코드로 옮겨 `ui/design` 에 둔다(ADR 0018). KMP 구현이 없어 직접 옮긴다. 색 238개와 다크 색 148개를 Kotlin 상수로, 아이콘을 vector 로, 컴포넌트를 Compose 로 옮긴다. 원티드 로고, 워드마크, 로딩 애니메이션은 가져오지 않는다. MIT 전문과 저작권 표시("Copyright (c) Wanted Lab, Inc."), Pretendard SIL OFL 1.1 고지를 `THIRD_PARTY_LICENSES.md` 와 앱 정보 화면에 넣는다.

| 구분 | 그리는 방법 |
|---|---|
| 화면 전부(버튼, 칩, 입력, 카드, 진행 막대, 상단 바, 대화상자 모양) | Montage 컴포넌트 |
| 하단 탭 | 네이티브. Android 는 Material 3 Expressive NavigationBar 계열로 최상위 탭 화면에서만 보인다. iOS 는 SwiftUI TabView 와 Liquid Glass 로 하위 화면에도 남는다. 시험 진행과 녹음 화면은 두 플랫폼 모두 탭이 없다 |
| 뒤로가기 | 네이티브. Android 는 예측 뒤로가기, iOS 는 뒤로 버튼과 가장자리 스와이프 |
| 시스템 알림창, 권한 대화상자 | 시스템이 그린다 |
| 네이티브 후보(아직 정하지 않음) | 공유 시트, 파일 고르기(F6.3 문항 불러오기, F8.3 내보내기), 텍스트 입력 키보드 위 도구 |

강조색은 Montage 기본 파랑(`#0066FF`) 대신 말하기 등급 표에서 Advanced 구간에 흔히 쓰이는 주홍 계열을 쓴다. 앱의 목표 등급(AL)을 떠올리게 하는 색이다. 다른 기관의 로고나 그림은 쓰지 않고 색만 쓴다. 시맨틱 색 가운데 brand 계열만 이 색으로 바꾼다.

| 쓰는 곳 | 값 | 대비 |
|---|---|---|
| 라이트: 버튼, 글자, 선택 표시 | `#C83F1A` | 흰 글자 대비 5.02:1 |
| 라이트: 등급 그래프, 진행 막대 같은 장식 | `#E9572B` | 흰 글자 대비 3.58:1 이라 글자 배경에는 쓰지 않는다 |
| 다크 | `#FF8A62` | `#1B1C1E` 위 7.36:1. 위에 올리는 글자는 검정 계열 |

다크 배경의 실제 값은 Montage 를 옮기는 노드(`c5`)에서 다시 잰다.

네이티브로 그리는 부분은 미리 확인 노드(`s4`)에서 관리 비용을 잰다. 아래 넷 중 하나라도 해당하면 하단 탭과 뒤로가기도 Montage 로 그려 두 플랫폼을 완전히 통일한다.

1. 네이티브 탭이나 뒤로가기 때문에 플랫폼별 코드가 화면 노드마다 생긴다. 하위 화면 탭 표시 차이(Android 숨김, iOS 유지)를 앱 틀의 화면 경로 표 하나로 처리하지 못하고 화면마다 플랫폼 분기가 생기는 경우도 여기 든다
2. 스크린샷 테스트를 화면마다 플랫폼별로 따로 만들어야 한다
3. 탭 바 높이와 안전 영역 여백을 Android, iOS 두 쪽에서 따로 계산해 Compose 화면에 넘겨야 하고, 그 값이 화면마다 다르게 쓰인다
4. iOS TabView 안에 Compose 화면을 넣었을 때 탭을 오갈 때마다 화면 상태가 사라지거나, 시험 중 탭 숨기기가 한 줄 설정으로 안 된다

## 6. AI 품질 관리

정답 등급 없이 하는 세 가지를 프롬프트를 고칠 때마다 같은 입력으로 다시 돌린다.

1. 같은 입력 5번: 등급이 몇 번 같게 나오는지
2. 일부러 틀린 답: 시제, 관사 오류를 넣은 대본을 기기 음성으로 읽혀 교정이 잡는 비율
3. 수준 다른 답 셋: 같은 문항을 NL, IM, AL 수준으로 써서 등급 순서가 맞는지

결과는 `evals/reports/` 에 프롬프트 버전별 표로 남긴다.
