# 제품 요구사항

실제 오픽 한 회를 그대로 체험하는 모의시험과, 질문 하나만 푸는 한 문항 연습을 주는 앱이다. 답변마다 AI 피드백이 쌓이고, 모의시험은 예상 등급 범위가 나온다. 모의시험은 앱을 껐다 켜도 이어서 풀 수 있어 틈새 시간에 나눠 본다. Compose Multiplatform 으로 Android, iOS 를 같이 만들고 오픈소스로 공개한다.

설계는 `design.md`, 설계 결정은 `../adr/` 에 있다.

## 1. 목표

오픽 AL 을 목표로 하는 사용자가 실제 시험과 같은 조건에서 연습하고, 답변마다 무엇을 고칠지 안다.

## 2. 범위

넣는 것: 모의시험 15문항, 이어 보기, 한 문항 연습, 답변별 피드백, 회차 예상 등급, 회차별 기록, 약점 출제, 틀린 교정 표시.

| 뺀 것 | 이유 |
|---|---|
| 서버, 계정 | 사용자가 자기 Gemini 키를 쓴다 |
| 정한 시각에 울리는 전화 | 알람 권한, 꽉 찬 화면 권한, 재부팅 재등록, iOS AlarmKit 처리가 따라붙는데 연습의 핵심이 아니다 |
| 3문항 짧은 회차 | 한 문항 연습이 그 역할을 한다 |
| 채점 정확도 측정, 직접 채점 정답지 | 정답 등급을 얻으려면 실제 시험을 보거나 직접 채점해야 한다. 틀린 교정 표시가 쌓이면 나중에 정답지로 쓴다 |

## 3. 사용자 흐름

**처음 실행.** 시스템 스플래시가 떠 있는 동안 앱이 키와 동의 상태를 읽고 갈 곳을 정한다. 키가 없으면 키 입력 화면에 머문다. 키를 넣은 뒤 녹음한 음성이 Google Gemini 로 간다는 안내에 동의해야 홈으로 간다. 두 플랫폼 모두 같다.

**모의시험.** 서베이(지난 선택으로 채워져 있음), 수준 선택(1~6), 마이크 점검과 연습 문항, 1~7번, 난이도 재조정, 8~15번 순으로 간다. 끝나면 리포트가 나온다. 중간에 앱을 꺼도 다시 켜면 멈춘 문항에서 이어진다.

**한 문항 연습.** 홈에서 "한 문항 풀기"를 누르면 약점 유형에서 질문 하나가 나오고, 답하면 바로 피드백이 나온다.

**리포트와 기록.** 답변마다 전문, 교정, 한 등급 위 표현, 시제와 문단 길이와 속도와 멈춤을 본다. 모의시험은 예상 등급 범위와 근거가 붙는다. 기록 화면은 회차별 예상 등급 변화를 보여 준다.

## 4. 기능 요구사항

각 항목이 수락 기준이다. 테스트로 확인할 수 있게 쓰고, 이슈와 테스트가 이 번호를 가리킨다.

### F1. 첫 실행

- F1.0 앱은 시스템 스플래시(Android SplashScreen API 의 `setKeepOnScreenCondition`, iOS 실행 화면)를 잡아 둔 채 저장된 상태만 읽고, 키가 없으면 S1, 동의 전이면 S2, 둘 다 되어 있으면 홈으로 보낸다. 스플래시를 따로 그리지 않는다. 키 확인 요청은 여기서 보내지 않는다
- F1.1 키를 넣으면 Gemini 에 짧은 요청을 보내 키가 맞는지 확인한다. 틀리면 이유를 보여 주고 저장하지 않는다
- F1.2 키는 Android 에서 Keystore AES-GCM 키로 암호화해 DataStore 에, iOS 에서 Keychain(`AfterFirstUnlockThisDeviceOnly`)에 둔다
- F1.3 두 플랫폼 모두 동의 전에는 어떤 녹음도 전송하지 않는다. 동의는 사용자가 버튼을 눌러야 성립하고, 뒤로가기나 홈으로 나가는 것은 동의가 아니다. 동의 화면은 마이크 권한 요청(S6)보다 먼저 나온다. 설정에서 동의를 철회하면 대기 중인 전송도 멈추고 다음 실행 때 S2 로 간다

### F2. 모의시험 진행

- F2.1 화면 순서는 서베이, 수준 선택, 점검, 연습 문항, 1~7번, 재조정, 8~15번, 끝이다. 수준 1~2 는 12문항이다
- F2.2 서베이 Part 4 에서 12개 미만이면 다음으로 못 간다. 지난 선택을 미리 채운다
- F2.3 문항 화면에 질문 글자는 없다. Play 를 누르면 질문을 기기 음성으로 읽고 끝나면 녹음이 저절로 시작된다
- F2.4 녹음 시작 5초 안에만 다시 듣기 한 번. Next 는 녹음 10초 뒤에 켜진다. 지나간 문항으로 못 간다
- F2.5 40분 타이머는 1번에서 시작하고 문항 화면을 벗어나 있는 동안(나가기, 앱 종료) 멈춘다. 기기 시각을 바꿔도 흔들리지 않는다
- F2.6 40분이 지나면 답한 문항까지만 채점하고 남은 문항은 "시간 부족"으로 표시한다
- F2.7 문항별 답변 타이머는 기본으로 끄고 설정에서 켠다

### F3. 이어 보기

- F3.1 진행은 공통 코드의 순수 함수 하나가 계산한다. 상태가 바뀔 때마다 통째로 저장한다
- F3.2 녹음은 몇 초 단위 조각 파일로 바로 쓴다. 앱이 죽으면 쓰던 조각 하나만 잃는다
- F3.3 다시 켜면 같은 문항에서 이어 녹음한다. 그 문항에서 다시 듣기를 안 썼으면 한 번 들을 수 있다
- F3.4 진짜 전화나 Siri 가 끼어들면 그 구간을 표시하고, 끝나면 새 조각으로 다시 녹음한다
- F3.5 화면이 꺼지거나 다른 앱으로 가도 녹음은 이어진다(Android 마이크 서비스, iOS 백그라운드 오디오)

### F4. 한 문항 연습

- F4.1 홈에서 언제든 시작한다. 질문 하나, 모의시험과 같은 문항 규칙
- F4.2 답하면 피드백을 바로 보여 준다

### F5. AI 분석

- F5.1 Next 를 누르면 그 답변을 바로 분석 대기열에 넣는다. 15개를 한꺼번에 보내지 않고 순서대로 보낸다
- F5.2 답변 피드백: 전문, 교정(원문 구절과 고친 문장), 한 등급 위 표현, 시제 유지, 문단 길이, 말 속도, 멈춘 시간, 롤플레이에서 한 질문 수
- F5.3 회차 등급: 15번이 끝나면 답변 피드백과 녹음을 묶어 한 번 보낸다. ACTFL 기준 문장을 예/아니오 체크리스트로 채우고, 체크 결과로 등급 범위(예: IH ~ AL)와 근거를 정한다
- F5.4 앱 코드 검사: 교정의 원문 구절이 전문에 있어야 한다. 값 범위, 문항 수, 주제를 확인한다. 통과 못하면 한 번 다시 요청하고 그래도 안 되면 그 항목을 버린다
- F5.5 무음, 한국어, 5초 미만 녹음이면 이유 코드를 돌려받고 "평가할 수 없음"으로 보여 준다
- F5.6 오프라인이면 녹음은 그대로 하고 분석은 대기열에 둔다. 429, 408, 5xx 만 지수 백오프로 최대 3회 재시도한다. 실패해도 녹음은 남는다
- F5.7 모델 이름은 특정 버전으로 고정하고, 결과마다 `model` 과 `promptVersion` 을 저장한다

### F6. 출제

- F6.1 Gemini 가 서베이 주제, 수준, 재조정 선택, 약점 점수를 받아 문항 유형 순서에 맞춰 질문을 만든다
- F6.2 생성이 실패하면 앱에 넣어 둔 문항 풀에서 서베이 주제로 고른다. 내장 문항은 직접 쓴다. 기출 원문은 넣지 않는다
- F6.3 사용자는 자기 문항 파일(JSON)을 불러올 수 있다

### F7. 리포트와 기록

- F7.1 답변 리포트: F5.2 의 항목. 한 문항 연습과 모의시험 답변이 같은 화면을 쓴다
- F7.2 회차 리포트: 등급 범위, 근거, 어느 문항에서 무너졌는지, 15개 답변 목록
- F7.3 기록: 회차별 예상 등급 변화, 문항 유형별 약점

### F8. 틀린 교정 표시

- F8.1 교정 항목마다 "틀림"을 누를 수 있다
- F8.2 틀림으로 표시한 교정은 약점 점수 계산에서 뺀다
- F8.3 표시한 교정은 원래 답변 전문, 교정 내용, `model`, `promptVersion` 과 함께 기기에 남는다. 설정에서 JSON 으로 내보낼 수 있다. 서버가 없으니 사용자가 원하면 저장소 이슈에 붙인다
- F8.4 쌓인 표시는 프롬프트를 고칠 때 오류 분석 재료로 쓴다(`docs/error-analysis.md`)

## 5. 비기능 요구사항

| 항목 | 기준 |
|---|---|
| 플랫폼 | Android 9.0(API 28) 이상, targetSdk 36, iOS 18 이상 |
| 화면 | edge-to-edge 를 켜고 공용 화면 틀이 시스템 바와 키보드 인셋을 처리한다. 뒤로가기는 Navigation 3 기본 동작에 맡기고, 시험 중 나가기처럼 막아야 하는 화면만 가로챈다(예측 뒤로가기 애니메이션 유지) |
| 모듈 | 앱, 화면, 시험 팩, 엔진, 라이브러리 다섯 층. 오픽 내용은 시험 팩 하나에만. 라이브러리는 떼어 쓸 수 있게 다른 모듈 의존 0개 |
| 저장 | Room 3.0 (KMP). 녹음 파일은 기기에만 |
| 전송 | 답변 녹음은 전송 직전 한 파일로 합쳐 요청에 바로 넣는다. 요청 크기는 20MB 를 넘지 않게 한다(2분 답변은 약 1MB) |
| 백그라운드 | Android WorkManager 고유 작업(답변 ID 단위), iOS 는 DB 대기열을 앱이 앞으로 올 때 비운다 |
| 시간 | 실행 중엔 단조 시계로 재고, 조각이 끝날 때마다 누적 시간을 DB 에 더한다 |
| 개인정보 | 동의 전 전송 없음. 동의 화면에 18세 이상, EEA 등 무료 등급 제한 지역 안내. 앱 안과 스토어에 개인정보처리방침 링크 |
| 백업 | 녹음 폴더와 암호화된 키를 자동 백업에서 뺀다. 키는 다른 기기에서 풀 수 없고, 녹음이 커지면 나머지 백업이 막힌다 |
| 로그, 네트워크 | 릴리스 빌드는 답변 내용과 키를 로그에 남기지 않는다. 평문 통신을 막는 네트워크 보안 설정을 둔다 |
| 스토어 신고 | Play Data safety 에 음성 녹음 수집, 마이크 포그라운드 서비스 용도 신고와 시연 영상, App Store 개인정보 항목 |

## 6. AI 품질 관리

정답 등급 없이 하는 세 가지를 프롬프트를 고칠 때마다 같은 입력으로 다시 돌린다.

1. 같은 입력 5번: 등급이 몇 번 같게 나오는지
2. 일부러 틀린 답: 시제, 관사 오류를 넣은 대본을 기기 음성으로 읽혀 교정이 잡는 비율
3. 수준 다른 답 셋: 같은 문항을 NL, IM, AL 수준으로 써서 등급 순서가 맞는지

결과는 `evals/reports/` 에 프롬프트 버전별 표로 남긴다.

## 7. 완료 기준

- F1~F8 의 수락 기준이 모두 테스트로 확인된다. 진행 상태 계산은 앱 꺼짐, 40분 끝, 7번 뒤 재조정을 포함한 모든 조합을 단위 테스트로 본다
- `./gradlew check` 하나로 공통 테스트, Android 테스트, iOS 시뮬레이터 테스트, 린트, 스크린샷 테스트가 돈다
- 두 기기(Android, iPhone)에서 모의시험 한 회를 끝까지 보고 리포트를 받는다. 중간에 앱을 강제 종료하고 이어 보기를 한 번 한다
- 설계 결정 기록 19개가 `docs/adr/` 에 있다
- README 에 AI 를 어디까지 썼는지 적는다

## 8. 위험

| 위험 | 대응 |
|---|---|
| AI 등급이 후하게 나온다 | 등급 하나 대신 범위와 근거. 체크리스트로 판정 |
| 기기 음성이 실제 시험 음성과 너무 다르다 | 첫 시험 구현에서 듣고 판단. 안 되면 Gemini 음성으로 미리 만든다 |
| 무료 키 한도(429)에 자주 걸린다 | 순서대로 보내고 백오프. 한도 초과는 "언제 다시 되는지"를 보여 준다 |
| App Store 가 사용자 키 방식(BYOK)을 문제 삼는다 | 이 방식을 직접 다룬 심사 조항은 찾지 못했다. 동의 화면과 심사 메모로 대응 |
