# AI 출력 오류 분석

이 문서는 Gemini 가 낸 피드백과 등급에서 틀린 것을 모아 종류별로 세고, 다음 프롬프트 버전에서 무엇을 고칠지 정하는 기록이다(F8.4). 2026-10-10 기준으로 모인 사례는 3건이고 모두 품질 확인 보고서에서 나왔다. 첫 보고서는 `evals/reports/opic-en-session-grade-v1_opic-en-answer-v2_gemini-3.8-flash.md` 다. 사용자 표시 파일은 아직 들어오지 않았다.

## 재료

| 재료 | 어디서 오나 | 무엇을 알 수 있나 |
|---|---|---|
| 틀린 교정 표시 | 앱 설정의 내보내기 JSON. 사용자가 저장소 이슈에 붙인다(F8.3) | 사용자가 틀렸다고 본 교정 하나하나. 항목마다 `transcript`, `original`, `corrected`, `provider`, `model`, `promptVersion` 이 있다 |
| 품질 확인 보고서 | `GEMINI_API_KEY=... ./gradlew :tools:eval:run` 이 `evals/reports/<등급 프롬프트>_<답변 프롬프트>_<모델>.md` 로 남긴다 | 같은 회차 5번의 등급 범위 일치 수, 일부러 넣은 오류 5개 중 교정이 잡은 수, NL, IM2, AL 대본의 등급 순서 |
| 출력 검사가 버린 항목 | `engine/answer` 의 `checkFeedback`, `checkSessionGrade` 가 돌려주는 `problems` | 모델이 전문에 없는 구절을 교정했거나 범위 밖 값을 낸 횟수 |

출력 검사가 버린 항목은 지금 기기 밖으로 나가지 않는다. 이 종류의 빈도가 필요해지면 표시 내보내기에 함께 넣는다.

## 오류 종류

사례를 받으면 아래 종류 하나로 나눈다. 앱 코드가 이미 거르는 종류는 사용자에게 보이지 않으니 프롬프트보다 비용(다시 요청 횟수)의 문제다.

| 종류 | 예 | 앱이 거르나 | 고칠 곳 |
|---|---|---|---|
| 없는 구절 교정 | 사용자가 하지 않은 말을 `original` 로 인용한다 | 거른다. 전문에 없는 교정과 표현은 버린다 | 답변 프롬프트의 인용 규칙 |
| 맞는 말을 틀렸다고 함 | 자연스러운 구어 표현을 문법 오류로 고친다 | 못 거른다. 사용자 표시로만 안다 | 답변 프롬프트, 구어 허용 예 |
| 받아쓰기 오류를 사용자 오류로 봄 | 발음이 비슷한 낱말을 잘못 받아쓰고 그 낱말을 교정한다 | 못 거른다 | 답변 프롬프트, 받아쓰기가 불확실한 구절 표시 |
| 이어 녹음 지점을 멈춤으로 셈 | 앱이 꺼졌다 켜진 지점을 긴 멈춤으로 보고한다 | 못 거른다. `resumedAt` 을 프롬프트에 넣는다 | 답변 프롬프트의 `resumedAt` 설명 |
| 범위 밖 값 | 점수가 0~100 밖, 음수 문장 수, 등급 체계 밖 이름, 문항 수 밖 번호 | 거른다. 한 번 다시 요청하고 또 틀리면 버릴 수 있는 항목은 버리고, 점수나 등급 범위처럼 버릴 수 없는 값이면 분석을 거절한다 | 응답 스키마 |
| 등급이 후하다 | 체크리스트 답과 맞지 않게 높은 범위를 준다 | 못 거른다 | 회차 등급 프롬프트의 체크 문장 |
| 같은 입력에 등급이 흔들린다 | 같은 회차 5번 중 범위가 셋 이상으로 갈린다 | 못 거른다 | 회차 등급 프롬프트, 답이 갈린 체크 문장 |
| 오류를 놓침 | 문법 오류가 있는 구절을 교정하지 않는다 | 못 거른다. 품질 확인 보고서의 넣은 오류로만 안다 | 답변 프롬프트의 교정 규칙 |

## 사례 기록

사례를 하나씩 줄로 더한다. 원문은 사용자가 말한 내용이라 전문 대신 문제 구절만 적는다.

| 날짜 | 출처 | 프롬프트 버전 | 모델 | 종류 | 문제 구절 | 처리 |
|---|---|---|---|---|---|---|
| 2026-10-10 | 품질 확인 보고서 | `opic-en-session-grade-v1` | gemini-3.8-flash | 등급이 후하다 | IM2 수준 대본 회차가 두 번 돌린 10번 모두 IM3~IH 를 받았다 | 다음 등급 프롬프트 버전에서 IM2 대본이 충족했다고 답한 체크 문장을 보고 고친다 |
| 2026-10-10 | 품질 확인 보고서 | `opic-en-session-grade-v1` | gemini-3.8-flash | 같은 입력에 등급이 흔들린다 | NL 수준 대본이 첫 번째 실행에서 NL~NH, 두 번째 실행에서 NL~NM 을 받았다. 첫 번째 실행의 같은 입력 5번에서는 C7 이 갈렸다 | 지켜본다. 5번 안에서는 범위가 하나로 모였다 |
| 2026-10-10 | 품질 확인 보고서 | `opic-en-answer-v2` | gemini-3.8-flash | 오류를 놓침 | `a umbrella` 를 첫 번째 실행은 잡고 두 번째 실행은 놓쳤다 | 지켜본다. 관사 오류가 다시 빠지면 답변 프롬프트에 관사 예를 넣는다 |

## 프롬프트 버전별 요약

| 프롬프트 버전 | 같은 범위 (5번 중) | 넣은 오류를 잡은 수 (5개 중) | 등급 순서 | 사용자 표시 수 | 다음에 고칠 것 |
|---|---|---|---|---|---|
| `opic-en-answer-v2`, `opic-en-session-grade-v1` | 5 (IM3~IH, 대본 수준은 IM2) | 4 (첫 번째 실행은 5) | 맞다 (NL~NM, IM3~IH, AL~AL) | 0 | 회차 등급 프롬프트가 IM2 대본을 한 단계 높게 본다. 다음 등급 프롬프트 버전에서 고친다 |

## 절차

1. 프롬프트를 고치기 전에 지금 버전으로 품질 확인 보고서를 만든다. 한 번 돌리는 데 요청 8번이 든다(회차 등급 7번, 답변 분석 1번)
2. 이슈에 붙은 표시 JSON 을 사례 기록 표에 옮기고 종류를 나눈다
3. 가장 많은 종류 하나를 골라 프롬프트를 고치고 `promptVersion` 을 올린다
4. 같은 입력(`tools/eval/inputs.json`)으로 보고서를 다시 만들어 요약 표에 한 줄을 더한다. 세 지표 중 하나라도 나빠지면 그 버전을 내보내지 않는다
