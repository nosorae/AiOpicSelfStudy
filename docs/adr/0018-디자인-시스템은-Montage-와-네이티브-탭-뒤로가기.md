# 0018. 디자인 시스템은 Montage 를 공통 코드로 옮기고 하단 탭과 뒤로가기만 네이티브로 그린다

- 상태: 채택
- 날짜: 2026-10-09

## 배경

화면은 Compose Multiplatform 으로 두 플랫폼에 한 벌만 만든다. 라이트와 다크 색, 글꼴, 컴포넌트를 처음부터 짜면 화면 노드마다 색과 간격을 새로 정하게 되고 두 테마의 대비를 맞추는 일이 계속 생긴다. 한편 하단 탭과 뒤로가기는 사용자가 OS 마다 손에 익힌 동작이라 한 벌로 통일하면 한쪽 플랫폼 사용자가 어색해한다.

## 후보

1. Material 3 Expressive 컴포넌트에 Pretendard 글꼴만 얹는다
2. Montage 토큰에 Material 3 컴포넌트를 섞어 쓴다
3. Montage(MIT) 토큰과 컴포넌트를 통째로 옮기고, 하단 탭과 뒤로가기만 플랫폼 네이티브로 그린다
4. 3과 같되 하단 탭과 뒤로가기도 Montage 로 그려 완전히 통일한다

## 결정

3을 고른다. Montage v4.0.0 태그의 토큰(색 238개, 다크 색 148개), Pretendard 4종, 아이콘 vector, 컴포넌트를 commonMain 의 `ui/design` 으로 옮긴다.

- 하단 탭: Android 는 Material 3 Expressive NavigationBar 계열, iOS 는 SwiftUI TabView 와 Liquid Glass. 하위 화면의 탭 표시는 플랫폼을 따른다. Android 는 최상위 탭 화면(홈, 기록, 설정)에서만 보이고 하위 화면에서 숨긴다. iOS 는 리포트 상세 같은 하위 화면에도 남긴다. 시험 진행과 녹음 화면은 두 플랫폼 모두 탭 없는 전체 화면이다
- 뒤로가기: Android 예측 뒤로가기, iOS 뒤로 버튼과 가장자리 스와이프
- 플랫폼별 코드는 앱 틀(`apps/opic`) 한 곳에만 둔다. 어느 화면에서 탭을 보일지는 앱 틀의 화면 경로 표 하나에 두고 화면 모듈은 플랫폼을 모른다
- 원티드 로고, 워드마크, 로딩 애니메이션은 가져오지 않는다. MIT 전문과 저작권 표시, Pretendard SIL OFL 1.1 고지를 `THIRD_PARTY_LICENSES.md` 와 앱 정보 화면에 둔다
- 강조색은 Montage 기본 파랑 대신 우리 주홍이다. 시맨틱 색 가운데 brand 계열만 바꾼다

| 쓰는 곳 | 값 | 대비 |
|---|---|---|
| 라이트: 버튼, 글자, 선택 표시 | `#C83F1A` | 흰 글자 대비 5.02:1 |
| 라이트: 등급 그래프, 진행 막대 같은 장식 | `#E9572B` | 흰 글자 대비 3.58:1. 글자 배경에는 쓰지 않는다 |
| 다크 | `#FF8A62` | `#1B1C1E` 위 7.36:1. 위에 올리는 글자는 검정 계열 |

### 화면 모드

설정에 "시스템 따라가기", "라이트", "다크" 선택을 두고 기본값은 시스템 따라가기다. 두 플랫폼이 같은 설정 화면을 쓴다. Android 9 기기는 시스템 다크 설정이 없어서 앱 안 선택이 없으면 다크를 쓸 수 없다. Montage 는 라이트와 다크 토큰이 함께 있어 이 값으로 토큰 묶음만 고른다.

## 이유

라이트와 다크가 함께 맞춰진 팔레트와 컴포넌트를 두 플랫폼에 한 벌로 쓰면 화면 노드는 토큰만 꺼내 쓰고, 스크린샷 테스트도 화면마다 한 벌이다. 후보 1은 컴포넌트 모양이 Android 쪽으로 기울어 iOS 화면이 낯설고, 후보 2는 두 체계의 간격과 모서리 값이 섞여 화면마다 맞추는 일이 생긴다. 하단 탭과 뒤로가기는 화면 밖 틀이라 앱 틀 한 곳에서만 플랫폼 코드를 가지면 되고, 사용자는 OS 에 익은 이동 동작을 그대로 쓴다. 하위 화면에서 탭을 숨기느냐 남기느냐도 각 OS 사용자가 익숙한 쪽을 따른다. 시험 진행과 녹음은 다른 탭으로 새면 시험 규칙이 깨져 두 플랫폼 모두 탭을 없앤다.

강조색 주홍은 말하기 등급 표에서 Advanced 구간에 흔히 쓰이는 색 계열이라 앱의 목표 등급(AL)을 떠올리게 한다. 다른 기관의 로고나 그림은 쓰지 않고 색만 쓴다. 장식용 `#E9572B` 는 흰 글자 대비가 4.5:1 에 못 미쳐 글자 배경에서 뺐다.

## 결과

Montage 는 KMP 구현이 없어 직접 옮기는 비용이 든다(노드 `c5`). 다크 배경의 실제 값은 옮길 때 다시 재서 위 대비를 확인한다.

네이티브 부분의 관리 비용은 미리 확인 노드 `s4` 에서 잰다. 다음 넷 가운데 하나라도 해당하면 후보 4(완전 통일)로 바꾸고 이 기록을 새 ADR 로 대체한다.

1. 플랫폼별 코드가 화면 노드마다 생긴다. 하위 화면 탭 표시 차이를 앱 틀의 경로 표 하나로 처리하지 못하고 화면마다 플랫폼 분기가 생기는 경우도 여기 든다
2. 스크린샷 테스트를 화면마다 플랫폼별로 따로 만들어야 한다
3. 탭 바 높이와 안전 영역 여백을 두 쪽에서 따로 계산해 화면마다 다르게 쓴다
4. iOS TabView 안 Compose 화면이 탭 전환에 상태를 잃거나, 시험 중 탭 숨기기가 한 줄 설정으로 안 된다
