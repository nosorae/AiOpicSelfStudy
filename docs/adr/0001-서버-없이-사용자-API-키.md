# 0001. 서버 없이 사용자 API 키를 쓴다

- 상태: 채택
- 날짜: 2026-10-09

## 배경

답변 녹음을 AI 로 분석해야 한다. 서버를 두면 계정, 인증, 과금, 녹음 보관을 운영해야 하고, 무료로 공개하는 오픈소스 앱에서 그 비용을 누가 낼지 정할 수 없다.

## 후보

1. 우리 서버가 Gemini 를 대신 부른다
2. 사용자가 자기 Gemini API 키를 앱에 넣는다(BYOK)

## 결정

서버를 두지 않는다. 사용자가 자기 Gemini 키를 넣고, 앱이 Gemini 를 바로 부른다.

- 키는 Android Keystore AES-GCM 으로 암호화해 DataStore 에, iOS 는 Keychain(`AfterFirstUnlockThisDeviceOnly`)에 둔다
- 키를 넣을 때 짧은 요청으로 맞는지 확인하고, 틀리면 저장하지 않는다
- 키와 녹음은 자동 백업에서 뺀다

## 이유

운영할 서버가 없으니 비용과 장애 지점이 사용자 기기와 Gemini 둘로 줄어든다. 녹음이 우리 쪽에 쌓이지 않아 개인정보 처리 범위가 작다. 사용자는 무료 키로도 연습할 수 있다.

## 결과

키를 처음 받는 단계가 사용자에게 진입 장벽이 된다. 무료 키 한도(429)에 걸리면 순서대로 보내고 백오프하며 언제 다시 되는지 보여 준다. 사용자 키 방식을 직접 다룬 스토어 심사 조항은 찾지 못해, 동의 화면과 심사 메모로 대응한다.
