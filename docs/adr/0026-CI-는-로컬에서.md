# 0026. 검증은 로컬에서 하고 GitHub CI 는 수동 실행으로 둔다

- 상태: 0033 으로 대체
- 날짜: 2026-10-10

## 배경

GitHub Actions 무료 시간을 다 썼다. macOS 잡은 Linux 보다 시간이 열 배로 계산돼서 iOS 확인이 시간을 대부분 쓴다. 노드마다 PR 을 바로 병합하고 CI 결과를 기다리지 않았으니, CI 는 병합을 막지 못하고 시간만 쓰고 있었다.

## 후보

1. 유료 시간을 산다
2. 잡을 Linux 하나로 줄인다
3. 자동 실행을 끄고, 같은 검증을 pre-push 훅과 병합 전 로컬 `./gradlew check` 로 한다. 워크플로 파일은 수동 실행으로 남긴다

## 결정

3을 고른다. `ci.yml` 의 트리거를 `workflow_dispatch` 하나로 바꾼다.

## 이유

이 저장소의 병합 기준은 처음부터 로컬 종료 코드였다(0016, 0020). pre-push 훅이 민감 정보 검사와 `./gradlew check` 를 돌고, 맥에서 도는 check 는 iOS 시뮬레이터 테스트까지 포함한다. 2로 가면 iOS 확인이 빠져 로컬보다 약한 검사가 된다.

## 결과

Linux 에서 찍은 스크린샷 비교처럼 다른 운영체제에서만 드러나는 차이는 자동으로 보지 않는다. 공개 전이나 큰 변경 뒤에 Actions 화면에서 수동으로 한 번 돌린다.
