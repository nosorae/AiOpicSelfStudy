# 0016. 이슈를 먼저 만들고 노드마다 PR 하나를 바로 병합한다

- 상태: 채택
- 날짜: 2026-10-09

## 배경

사람과 에이전트가 같은 저장소를 고친다. 어떤 줄이 어떤 요구 때문에 들어왔는지 거슬러 올라갈 수 있어야 하고, 에이전트 여럿이 동시에 일해도 기다림이 길지 않아야 한다.

## 후보

1. main 에 바로 커밋한다
2. 로컬에서 병합하고 PR 은 만들지 않는다
3. 이슈를 먼저 만들고, 노드마다 브랜치와 PR 하나를 만든 뒤 CI 를 기다리지 않고 바로 병합한다

## 결정

추적되는 파일을 바꾸는 일은 모두 이슈를 먼저 만든다. 브랜치는 `node/<노드id>`, PR 은 노드 하나에 하나이고 이슈와 PR 은 템플릿 하나씩을 쓴다. 병합 전에 main 으로 rebase 하고 squash 로 바로 병합한다. CI 는 기다리지 않고, 깨지면 고치는 이슈를 새로 만든다. UI 가 바뀌는 PR 은 전후 스크린샷을 붙인다.

## 이유

모든 변경이 이슈 하나에서 시작해 PR 하나로 닫혀 요구사항에서 코드까지 거슬러 올라갈 수 있다. 로컬 검사(`./gradlew check`)가 이미 같은 명령을 돌리므로 CI 를 기다리는 시간을 없앤다. 화면 변경은 글보다 전후 이미지로 바로 확인한다.

## 결과

CI 가 늦게 깨질 수 있다. main 푸시에서 이전 CI 실행을 취소하지 않아 어느 병합이 깨뜨렸는지 찾는다.
