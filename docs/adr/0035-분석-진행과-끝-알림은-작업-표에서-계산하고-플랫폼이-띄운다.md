# 0035. 분석 진행과 끝 알림은 작업 표에서 계산하고 플랫폼이 띄운다

- 상태: 채택
- 날짜: 2026-10-12

## 배경

모의고사 한 회차는 답변 15개 분석과 등급까지 몇 분이 걸린다. 사용자가 그동안 다른 앱으로 가면 분석이 도는지, 끝났는지 알 길이 없었다. Android 는 화면이 없는 동안 WorkManager 작업이 언제든 멈출 수 있고, iOS 는 앱이 뒤로 가면 곧 앱을 멈춘다.

## 후보

1. 화면마다 진행을 보이고 앱 밖 표시는 두지 않는다: 지금과 같다. 앱을 나가면 아무것도 안 보인다
2. 진행과 끝 알림 내용을 분석 작업 표(ADR 0032)에서 공통 코드가 계산하고, 띄우는 일만 플랫폼이 한다
3. 플랫폼 대기열이 비우면서 직접 진행을 센다: 대기열은 작업 상태를 모르도록 나눠 두었다(ADR 0032). 대기열이 상태를 세면 표와 어긋날 수 있다

## 결정

후보 2를 고른다.

- 진행은 비우기를 시작한 뒤 끝난 작업 수와 아직 남은 작업 수다(`analysisProgress`). 남은 작업이 없으면 진행 표시를 내린다
- 끝 알림은 비우기가 끝났을 때 남은 작업이 없고, 그 사이 끝난 작업이 있고, 앱이 화면에 없을 때만 띄운다(`drainAndNotify`). 실패가 있으면 실패 알림이다. 누르면 모의고사 답변은 회차 리포트, 연습 답변은 답변 리포트로 간다
- Android 는 분석 비우기 작업이 진행 알림을 단 데이터 동기화 포그라운드 서비스(`setForeground`)로 돈다. 앱이 화면에 없을 때 깨어나 서비스를 시작하지 못하면 알림 없이 그대로 비운다
- iOS 26 이상은 앱이 화면에 있을 때 기다리는 분석이 생기면 시스템 진행 표시(`BGContinuedProcessingTask`)를 요청한다. 비우기는 지금처럼 분석 대기열이 한다. 사용자가 진행 표시에서 멈추면 남은 작업을 취소 실패(`AnalysisError.Canceled`)로 끝내고, 리포트에 다시 분석하기가 보인다. 26 미만은 표시 없이 지금처럼 처리한다
- 알림 권한은 첫 분석을 시작할 때 한 번 묻는다. 거절해도 분석은 그대로 돈다

## 이유

- 상태는 작업 표 한 곳에 있다. 진행 숫자와 끝 판단을 같은 표에서 읽어야 리포트 화면과 알림이 다른 말을 하지 않는다
- 계산이 공통 코드 함수 둘이라 시각을 넣은 목록으로 호스트 테스트에서 확인한다. 플랫폼 코드에는 알림을 만들고 띄우는 일만 남는다
- 앱이 화면에 있으면 리포트 화면이 이미 기다림과 결과를 보이므로 끝 알림을 띄우지 않는다
- 포그라운드 서비스를 시작하지 못해도 분석을 멈추지 않는다. 진행 알림은 보조이고, 결과는 작업 표와 리포트가 지킨다

## 결과

- 진행은 비우기 한 번을 한 묶음으로 센다. 다시 보내기로 비우기가 나뉘면 뒤 비우기는 남은 것만 센다
- 끝 알림은 하나만 둔다. 새 결과가 앞 알림을 바꾼다
- iOS 진행 표시의 멈춤은 사용자가 멈춘 것과 시스템이 시간을 거둔 것을 가르지 못해 둘 다 취소로 남긴다. 시스템이 거두는 일이 잦으면 취소 대신 대기로 돌린다
- Play Console 에 데이터 동기화 포그라운드 서비스 신고와 시연 영상이 하나 더 든다(`fastlane/store-declarations.md`)
