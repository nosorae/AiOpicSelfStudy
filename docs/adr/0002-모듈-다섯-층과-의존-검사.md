# 0002. 모듈을 다섯 층으로 나누고 의존을 검사한다

- 상태: 채택
- 날짜: 2026-10-09

## 배경

같은 코드로 다른 언어 오픽이나 다른 말하기 시험 앱을 낼 수 있어야 한다. 시험 내용이 화면과 엔진에 섞이면 시험 하나를 더할 때마다 화면 코드를 고쳐야 한다. 녹음, Gemini 호출 같은 기능도 이 앱 밖에서 다시 쓸 수 있어야 한다.

## 후보

1. 모듈 하나(shared)에 모두 둔다
2. 기능별 모듈만 나누고 층 규칙은 두지 않는다
3. 앱, 화면, 시험 팩, 엔진, 라이브러리 다섯 층과 허용 표로 검사한다

## 결정

모듈 경로의 첫 마디를 층으로 삼는다(`apps`, `ui`, `packs`, `engine`, `libs`, 그 밖에 `tools`). 층마다 의존해도 되는 층을 `build-logic` 의 `LayerRules.kt` 표 하나에 두고, `./gradlew check` 의 `checkLayers` 가 어긴 의존을 찾으면 실패한다.

- libs 는 프로젝트 모듈을 의존하지 않고 explicit API 모드로 공개 API 를 드러낸다
- 화면은 시험 팩을 모른다. 앱 층이 팩을 조립해 넘긴다
- 층마다 convention 플러그인 id 하나를 건다

## 이유

시험 내용은 `packs/opic-en` 하나에만 있으니 다른 시험은 팩과 앱 모듈만 새로 만든다. 엔진과 라이브러리는 화면 없이 테스트한다. 규칙을 문서로만 두면 에이전트와 사람이 실수로 어겨도 모르는데, 검사가 빌드를 멈추고 고칠 방법을 찍어 준다. 검사는 수십 줄이라 외부 플러그인을 들이지 않고 직접 만든다.

## 결과

모듈이 20개 남짓으로 늘어 설정 비용이 생긴다. convention 플러그인과 경로로 만드는 namespace 가 그 비용을 줄인다. 층을 더하려면 허용 표를 고치고 이 기록을 대체한다.
