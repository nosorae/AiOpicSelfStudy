# 0022. 민감 정보는 저장소에 두지 않고 푸시 전과 CI 에서 막는다

- 상태: 채택
- 날짜: 2026-10-09

## 배경

저장소는 공개할 오픈소스다. 한 번 푸시된 키나 서명 팀 ID 는 히스토리에서 지워도 사본에 남는다. iOS 실기기 실행에는 개발 팀 ID 가, 실제 Gemini 호출을 재는 노드에는 API 키가 필요하다.

## 후보

1. 커밋할 때 사람이 눈으로 확인한다
2. 값을 저장소 안 설정 파일에 두고 저장소를 비공개로 유지한다
3. 기기마다 다른 값은 커밋하지 않는 파일에, API 키는 환경 변수에만 두고, 푸시 전과 CI 에서 같은 검사로 막는다

## 결정

3을 고른다.

- 서명 팀 ID 처럼 기기마다 다른 값은 커밋하지 않는 `apps/opic/iosApp/Configuration/Local.xcconfig`, `local.properties` 에 둔다. 예시 파일만 커밋한다
- Gemini API 키는 실제 호출이 필요한 노드에서 환경 변수 `GEMINI_API_KEY` 로만 읽는다. 파일에 적지 않는다. 테스트는 가짜 문자열을 쓴다
- `scripts/check-secrets.py` 가 커밋마다 새로 들어간 줄에서 키, 토큰, 서명 팀 ID, 개인 키, 개인 PC 절대경로 형태를 찾고, 커밋하지 않는 설정 파일이 들어갔는지 본다
- pre-push 훅과 CI 가 같은 스크립트를 돈다

## 이유

눈으로 하는 확인은 바쁠 때 빠진다. 비공개 저장소는 공개하는 순간 히스토리 전체가 드러난다. 값이 처음부터 저장소 밖에 있으면 실수로 들어갈 길이 줄고, 들어가도 푸시 전에 훅이, 훅을 설치하지 않은 환경에서는 CI 가 잡는다. 범위 전체가 아니라 커밋마다 보는 것은 중간 커밋에 들어갔다 빠진 값도 히스토리에 남기 때문이다.

## 결과

패턴에 없는 형태의 비밀 값은 잡지 못한다. 새 형태가 생기면 `check-secrets.py` 의 패턴에 더한다. 환경 변수가 없는 기기에서는 실제 호출 노드를 blocked 로 두고 사람을 부른다.
