# 0027. 교정마다 깎은 점수를 받아 틀림 표시만큼 되돌린다

- 상태: 채택
- 날짜: 2026-10-10

## 배경

사용자는 모델이 잘못 짚은 교정을 "틀림"으로 표시하고, 표시한 교정은 약점 점수 계산에서 빠져야 한다(F8.2). 지금까지 답변 프롬프트는 점수를 "문항 유형에 얼마나 맞는 답인가"로만 받고 교정과 점수를 잇지 않았다. 그래서 교정 하나를 점수 몇 점으로 바꿀 근거가 없어, 표시가 하나라도 붙은 답변을 평균에서 통째로 뺐다. 교정 다섯 개 중 하나만 틀려도 나머지 넷이 짚은 약점까지 사라진다.

## 후보

1. 답변을 통째로 뺀다: 지금 방식. 표시 하나에 맞게 짚은 교정까지 버린다
2. 교정 하나에 고정 점수(예: 5점)를 되돌린다: 교정마다 무게가 다른데 같은 값을 쓴다. 점수가 교정 수와 무관하게 나온 답변이면 되돌린 값이 근거 없이 100 을 넘나든다
3. 모델이 교정마다 깎은 점수를 함께 내게 하고, 표시한 교정의 몫만 되돌린다

## 결정

3번이다.

- 답변 응답 스키마의 교정에 `deducted`(0 이상 정수)를 필수로 받는다. 프롬프트 버전은 `opic-en-answer-v2` 다
- 출력 검사(F5.4)는 깎은 점수가 모두 0 이상이고 합이 `100 - score` 이하인지 본다. 어기면 한 번 다시 요청하고, 그래도 어기면 교정은 남기고 깎은 점수만 버린다(null)
- 약점 계산은 표시한 교정의 깎은 점수를 답변 점수에 더한다. 100 을 넘지 않게 자른다
- 표시한 교정에 깎은 점수가 없으면(v1 로 분석한 옛 답변, 출력 검사가 버린 값) 그 답변은 지금처럼 평균에서 뺀다

## 이유

교정마다 무게를 아는 쪽은 점수를 매긴 모델이다. 같은 응답 안에서 점수와 깎은 몫을 함께 내게 하면, 표시 하나가 그 답변의 다른 교정과 점수를 건드리지 않는다. 합을 `100 - score` 로 묶으면 모든 교정을 틀림으로 표시해도 점수가 100 을 넘지 않아서 약점 순위가 뒤틀리지 않는다. 깎은 점수가 틀렸을 때 교정까지 버리면 사용자가 보던 교정이 사라지므로 점수 몫만 버린다.

## 결과

- 도메인 `Correction.deducted` 는 null 이 될 수 있다. 저장된 옛 답변을 다시 분석하지 않아도 읽힌다
- 모델이 깎은 몫을 실제 점수와 맞게 나누는지는 평가 도구로 아직 재지 않았다. 합 조건만 앱 코드가 확인한다
- 평가 도구(`tools/eval`)의 손으로 쓴 스키마도 같은 필드를 받는다. 시험 팩 응답 클래스를 바꿀 때 함께 고친다
