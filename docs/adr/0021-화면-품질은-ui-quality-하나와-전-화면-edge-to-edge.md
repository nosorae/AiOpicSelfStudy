# 0021. 화면 품질 기준은 ui-quality 스킬 하나에 두고 edge-to-edge 는 모든 화면에서 켠다

- 상태: 채택
- 날짜: 2026-10-09

## 배경

화면 노드를 여러 에이전트가 나눠 만든다. 터치 영역, 대비, 글자 크기, 시스템 바 처리 같은 기준이 노드마다 다르면 화면끼리 어긋나고 리뷰에서 같은 지적이 되풀이된다. 시스템 바 아래까지 그리는 edge-to-edge 도 화면마다 켜고 끄면 같은 앱 안에서 위아래 여백이 들쭉날쭉해진다.

## 후보

1. 기준을 따로 두지 않고 화면 노드마다 리뷰에서 맞춘다
2. 기준을 `CLAUDE.md`, 소스셋 규칙, 스킬 여러 곳에 나눠 적는다
3. 화면 품질 기준을 `.claude/skills/ui-quality` 하나에 두고, edge-to-edge 는 끄는 화면 없이 모든 화면에서 켠다

## 결정

3을 고른다.

- 화면을 만들거나 고치거나 리뷰할 때 `ui-quality` 를 먼저 읽는다. 공통 기준과 Android, iOS 세부 기준이 여기에만 있다
- 모든 화면에서 edge-to-edge 를 켠다. 배경과 스크롤 콘텐츠는 시스템 바 아래까지 그리고, 버튼과 글은 시스템 바, 컷아웃, 키보드 인셋 안쪽에 둔다
- iOS Compose 화면도 배경은 안전 영역 밖까지, 콘텐츠는 안전 영역 안에 둔다
- 인셋 처리는 공용 화면 틀이 맡는다. 화면마다 인셋을 따로 계산하지 않는다

## 이유

기준이 한 곳에 있어야 화면 노드와 리뷰 에이전트가 같은 것을 본다. 여러 곳에 나누면 한쪽만 고쳐져 어긋난다.

Android 16 기기에서는 앱이 edge-to-edge 를 끌 수 없다. 일부 화면만 끄면 Android 16 기기와 그 이전 기기에서 같은 화면이 다르게 그려지고, 스크린샷 기준 이미지도 기기마다 갈린다. 처음부터 모든 화면을 같은 방식으로 그리면 이 차이가 생기지 않는다.

## 결과

화면마다 인셋 처리를 빠뜨리면 버튼이 시스템 바에 가려진다. 공용 화면 틀과 스크린샷 테스트로 잡는다. 기준이 바뀌면 `ui-quality` 를 고치고 이 기록은 그대로 둔다.
