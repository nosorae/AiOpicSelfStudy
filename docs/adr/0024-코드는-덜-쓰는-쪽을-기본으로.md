# 0024. 코드는 덜 쓰는 쪽을 기본으로 하고 ponytail 플러그인으로 매 세션 불러온다

- 상태: 채택
- 날짜: 2026-10-09

## 배경

노드마다 다른 에이전트가 코드를 쓴다. 에이전트는 "나중을 위해" 인터페이스, 설정, 빈 뼈대를 만들기 쉽다. 쓰이지 않는 코드도 리뷰하고 테스트하고 고쳐야 해서, 노드가 늘수록 이 비용이 쌓인다.

## 후보

1. 리뷰에서 그때그때 지적한다
2. CLAUDE.md 에 원칙만 적는다
3. 원칙을 CLAUDE.md 에 적고, 같은 원칙을 세션 시작마다 불러오는 ponytail 플러그인(MIT)을 프로젝트 설정에서 켠다

## 결정

3을 고른다. `.claude/settings.json` 에 ponytail 마켓플레이스와 플러그인을 켜고, CLAUDE.md 3절에 순서(필요한가, 이미 있나, 표준과 플랫폼으로 되나, 최소 코드)를 적는다.

## 이유

리뷰에서 지적하면 이미 쓴 코드를 지우는 일이 된다. 규칙 파일에만 두면 긴 작업 중에 잊힌다. 플러그인은 세션마다 같은 원칙을 다시 넣어서, 노드를 맡은 에이전트가 처음부터 같은 기준으로 쓴다.

테스트에서 가짜로 바꿔 끼우는 경계(저장소, 외부 API, 플랫폼 기능)는 구현이 하나여도 인터페이스를 둔다. 0019 의 분석 포트처럼 다른 제공사를 붙이기로 한 곳도 같다. 입력 검증, 데이터 보존, 보안, 접근성은 줄이는 대상이 아니다.

## 결과

플러그인은 외부 저장소에 있어서 처음 열 때 마켓플레이스 신뢰를 한 번 묻는다. 플러그인을 못 쓰는 환경에서도 CLAUDE.md 3절만으로 같은 기준을 지킨다.
