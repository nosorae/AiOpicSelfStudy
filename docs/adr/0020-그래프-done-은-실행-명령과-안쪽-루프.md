# 0020. 그래프 노드의 완료 조건은 실행 명령이고 안쪽 루프는 템플릿 하나다

- 상태: 채택
- 날짜: 2026-10-09

## 배경

개발 그래프의 노드 `done` 이 문장이라 끝났는지를 에이전트가 읽고 판단했다. 같은 문장도 읽는 쪽에 따라 다르게 판정되고, 몇 번 실패하면 사람을 부르는지가 문서 문장에만 있어 스크립트가 지킬 수 없었다.

## 후보

1. 지금처럼 문장으로 두고 에이전트가 판정한다
2. 노드마다 명령과 반복 규칙(구현, 확인, 리뷰, 병합과 횟수 상한)을 각각 적는다
3. 노드 `done` 은 명령, 반복 규칙은 그래프 최상위 `loop` 템플릿 하나에 두고 노드가 상한만 덮어쓴다

## 결정

3을 고른다.

- `done`: 저장소 루트에서 실행할 명령. 종료 코드 0 이면 통과다. 사람이 확인해야 끝나는 노드만 `"human"` 이다
- `done_desc`: 사람이 읽는 완료 조건 설명
- `loop`: 단계 `implement`, `done`, `review`, `merge` 와 엣지. done 실패면 구현으로 최대 3번, 리뷰 반려면 구현으로 최대 2번 돌아가고, 넘으면 `blocked` 로 사람을 부른다
- 노드의 `loop`: `{"done": 5}` 처럼 상한만 덮어쓴다. 노드의 `attempts`: 단계별 실패 횟수 기록
- `scripts/graph/run_done.sh <노드id>` 가 명령을 돌리고 실패 횟수를 기록하고, 상한을 넘으면 `set_status.sh` 로 blocked 처리한다
- 실험 결과로 다음 노드가 바뀌는 분기 엣지는 넣지 않는다. 판정 기준은 노드 설명과 설계 문서에 둔다
- 순환 검사는 노드 사이 `dependsOn` 에만 한다. 안쪽 루프의 되돌아가는 엣지는 상한이 있어야 검사를 통과한다

## 이유

종료 코드는 누가 돌려도 같은 판정을 낸다. 반복 규칙이 모든 노드에 같으니 한 곳에 두어야 고칠 때 한 번만 고친다. 후보 2는 노드 41개에 같은 규칙을 복사해 하나만 고쳐도 어긋난다. 분기 엣지를 넣으면 그래프 검사와 일정 계산이 실험 결과를 알아야 해서 넣지 않는다.

## 결과

아직 없는 모듈의 테스트 태스크를 명령에 쓴다. 그 모듈을 만드는 것이 노드의 일이라 시작 전에는 명령이 실패한다. 실기기가 필요한 계측 테스트 명령은 기기가 붙어 있어야 돈다. 리뷰 반려는 리뷰 단계가 `run_done.sh <노드id> review` 로 기록한다.
