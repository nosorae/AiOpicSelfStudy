# 0029. 진동은 별도 라이브러리로 두고 시스템 설정을 따른다

- 상태: 채택
- 날짜: 2026-10-10

## 배경

움직임에 짧은 진동을 붙여 누름, 선택, 녹음 시작과 끝, 결과를 손으로도 알린다(#166). 진동은 Android 와 iOS 가 API 를 따로 가진 플랫폼 기능이고, 화면 여러 곳에서 부른다.

## 후보

1. 화면 모듈마다 expect/actual 로 플랫폼 진동을 직접 부른다
2. `libs/haptics` 라이브러리에 효과 종류(enum)와 재생 함수(fun interface) 하나만 공개하고, 구현은 internal 로 숨긴다. 화면은 `ui/design` 의 CompositionLocal 로 꺼내 쓴다
3. 진동 세기와 길이를 앱이 직접 정한 파형(VibrationEffect.createWaveform, Core Haptics 패턴)으로 낸다

## 결정

2를 고른다. 효과는 쓰임(Tap, Selection, RecordStart, RecordStop, Success, Warning, Error, Celebrate)으로 나누고, 플랫폼 진동 종류는 구현이 정한다. Android 는 `View.performHapticFeedback`, iOS 는 UIKit 진동기를 쓴다. 축하만 Android API 33 이상에서 Composition 으로 내고, 아니면 성공 효과로 대신한다. 설정에 진동 켜기/끄기를 두고(기본 켬) 앱 틀이 끄면 재생하지 않게 씌운다.

## 이유

- 라이브러리 층(프로젝트 의존 0개)에 두면 플랫폼 코드가 한 모듈에 모이고, 화면은 효과 이름만 안다. 화면 테스트와 스크린샷은 기본값(아무것도 안 함)으로 돌아서 진동 때문에 바뀔 것이 없다
- 시스템 터치 진동을 쓰면 사용자가 기기에서 끈 진동이나 줄인 세기를 그대로 따른다. 직접 만든 파형(3)은 이 설정을 무시하고, 기기마다 모터가 달라 같은 값이 다르게 느껴진다
- CompositionLocal 은 숨은 의존이라 이 저장소는 막아 두었다. 진동은 거의 모든 화면이 쓰는데 인자로 내리면 화면 함수 서명이 모두 바뀌어서 `LocalHaptics` 하나만 ktlint 허용 목록에 넣는다

## 결과

- 남발하지 않는다. 모든 버튼이 아니라 README 대응표의 순간에만 쓴다. 연습 앱이라 진동이 잦으면 말하는 데 방해가 되고, 자주 울리면 중요한 알림(오류, 등급 공개)이 묻힌다
- 손 느낌(세기, 축하 간격)은 에뮬레이터와 시뮬레이터로 확인할 수 없어서 실기기에서 사람이 본다. 값은 구현 파일의 `ponytail:` 주석 한 곳에 있다
- Android 축하 진동 때문에 `VIBRATE` 권한(설치 때 자동 허용)이 매니페스트에 들어간다
