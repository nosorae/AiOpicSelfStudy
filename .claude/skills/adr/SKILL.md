# ADR 쓰기

결정 하나에 문서 하나다. 나중에 들어온 사람이 "왜 이렇게 했나"를 코드 대신 이 문서로 알 수 있어야 한다.

## 파일 이름

`docs/adr/NNNN-제목.md`. 번호는 네 자리로 이어 붙이고, 제목은 한국어 낱말을 `-` 로 잇는다.

```bash
ls docs/adr | tail -1   # 마지막 번호를 확인하고 하나 더한다
```

예: `0005-상태는-UiState-하나와-MutableStateFlow.md`

## 형식

```markdown
# NNNN. 제목

- 상태: 채택 | 대체됨(NNNN) | 폐기
- 날짜: YYYY-MM-DD

## 배경
무슨 문제를 풀어야 했나. 이 앱에서 그 문제가 생기는 경우를 한두 문장으로.

## 후보
1. 후보 A: 한 줄 설명
2. 후보 B: 한 줄 설명

## 결정
고른 것 한 문장. 지킬 규칙이 있으면 목록으로.

## 이유
왜 그 후보인가. 다른 후보를 고르면 이 앱에서 무엇이 나빠지나.

## 결과
이 결정으로 생기는 비용, 남는 일, 바꿀 조건.
```

"배경" 대신 "문제"를 써도 된다. 후보가 사실상 하나였으면 버린 대안을 하나라도 적는다.

## 이유는 우리 사정으로

- 이유는 이 앱의 기술 사정(테스트, 플랫폼 차이, 빌드, 모듈 경계)과 제품 판단(사용자, 비용, 개인정보)으로만 쓴다
- 다른 회사, 다른 프로젝트, 문서 권고를 근거로 대지 않는다. 그 권고가 이 앱에서 무슨 일을 막는지로 바꿔 쓴다
- 결정을 만든 대화나 과정을 적지 않는다. 결과만 남긴다

## 결정을 바꿀 때

옛 문서를 고치지 않는다. 새 ADR 을 쓰고 옛 문서의 상태를 `대체됨(새 번호)` 로 바꾼다. 관련 규칙이 `architecture`, `testing` 스킬이나 `CLAUDE.md` 에 있으면 같은 PR 에서 함께 고친다.
