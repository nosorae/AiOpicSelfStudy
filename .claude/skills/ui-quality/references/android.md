# Android 규칙

대상은 Android 9~16(minSdk 28, targetSdk 36)이다. 공통 코드 화면이 Android 에서 그려질 때와 androidMain 코드에 적용한다. 규칙마다 확인 방법을 붙였다.

## 1. targetSdk 36 에서 바로 지킬 것

targetSdk 를 36 으로 올린 순간 기기 버전에 따라 동작이 바뀐다. 아래 셋은 화면을 새로 만들지 않아도 걸린다.

- **edge-to-edge 를 끌 수 없다.** Android 15 이상에서는 강제되고, Android 16 기기에서는 끄는 설정(`windowOptOutEdgeToEdgeEnforcement`)이 무시된다. 그래서 모든 버전에서 `enableEdgeToEdge()` 를 부르고 inset 을 직접 처리한다(R11). 버전마다 다르게 그리면 화면을 두 벌 확인해야 한다
- **`onBackPressed` 가 불리지 않는다.** Android 16 기기에서는 `onBackPressed` 와 `KEYCODE_BACK` 이 전달되지 않는다. 뒤로가기를 가로채는 코드는 `BackHandler` 나 `PredictiveBackHandler` 만 쓴다(R14). 모의시험 중 뒤로가기 확인 다이얼로그가 여기 걸린다
- **가장 짧은 변이 600dp 이상인 화면에서는 세로 고정이 무시된다.** 태블릿과 펼친 폴더블에서는 가로 화면이 그대로 나온다. 세로 고정에 기대지 말고 회전과 창 크기 변경에서 상태를 지킨다(R13)

## 2. Android 9~11 용 고정 색 구성

동적 색(배경화면에서 뽑은 색)은 Android 12 이상에만 있다. 9~11 에서는 앱이 정한 색 구성으로 돌아가야 한다. 이게 없으면 Material 기본 보라색이 그대로 나온다.

- 라이트와 다크 고정 `ColorScheme` 을 둘 다 테마 파일에 둔다. 동적 색을 쓰는지와 상관없이 둔다
- 고르는 순서는 "Android 12 이상이고 동적 색을 켰으면 동적 색, 아니면 고정 구성" 하나다. 버전 분기는 테마 파일 한 곳에만 둔다
- 시스템 다크 테마는 Android 10 부터 있다. Android 9 에서는 `isSystemInDarkTheme()` 가 false 라 라이트 구성만 보인다. Android 9 다크 화면은 따로 확인하지 않는다
- `error` 처럼 뜻이 정해진 색과 녹음 중 표시는 동적 색에서도 고정 구성 값과 같은 계열을 쓴다(R7)

확인: Android 9 와 11 에뮬레이터에서 앱을 띄워 색이 기본 보라색이 아닌 앱 색인지 본다. Android 11 은 라이트와 다크 둘 다 본다.

## 3. 확인 도구

- Roborazzi 스크린샷: 라이트, 다크, 글자 200%(`LocalDensity` 의 `fontScale = 2f`), Compact 360dp 폭, Medium 이상 폭 하나로 찍는다
- 접근성 자동 검사: Compose UI 테스트에서 `enableAccessibilityChecks()` 뒤 `tryPerformAccessibilityChecks()` (`ui-test-junit4-accessibility`, Compose 1.8.0 이상). 라벨 누락, 대비, 작은 터치 영역, 읽는 순서를 잡는다. 계측 테스트에서 동작한다. Robolectric 위에서 도는지는 확인하지 못했다
- 수동: TalkBack 으로 화면 한 바퀴, 기기 글자 크기 최대, Accessibility Scanner

## 4. 규칙

### 크기와 글자

**R1. 누르는 요소는 48x48dp 이상 눌리게 한다.** 직접 만든 클릭 요소에는 `minimumInteractiveComponentSize()` 를 붙인다. 눌리는 영역끼리 겹치지 않게 한다.
확인: 접근성 자동 검사의 터치 영역 항목. 아이콘 버튼은 테스트에서 `assertTouchHeightIsEqualTo(48.dp)` 이상.

**R2. 글자 크기는 sp, 나머지 크기는 dp 로 쓴다.** 글자에 dp 를 쓰거나 sp 를 dp 로 변환해 고정하지 않는다.
확인: 코드 검색으로 `fontSize = ` 뒤에 `.dp` 가 없는지 본다. 글자 200% 스크린샷에서 글자가 커졌는지 본다.

**R3. 본문은 12sp 이상, 한국어 본문은 Body Medium(14sp) 이상을 기본으로 한다.** Label Small(11sp)을 문단에 쓰지 않는다.
확인: 테마 외부에서 `fontSize` 를 직접 쓴 곳을 검색한다. 글자 스타일은 `MaterialTheme.typography` 에서만 가져온다.

**R4. 글자 200% 에서 잘리거나 겹치는 글자가 없어야 한다.** 글자를 담는 요소에 고정 높이를 주지 않는다(`heightIn(min = ...)` 을 쓴다). 버튼 글자와 내비게이션 라벨은 줄이 넘치면 글자를 줄이지 말고 레이아웃을 바꾼다. 긴 화면은 스크롤로 감싼다.
확인: Roborazzi 글자 200% 스크린샷을 화면마다 찍어 눈으로 본다. 실제 기기에서 설정 > 디스플레이 > 글자 크기 최대로 문항 화면과 리포트를 본다.

### 색과 대비

**R5. 색은 색 역할로만 쓴다.** 화면 코드에 `Color(0xFF...)` 를 쓰지 않는다. 바탕과 글자는 `primary` 와 `onPrimary` 처럼 짝으로 쓴다. `~Container` 색을 글자에 쓰지 않는다.
확인: 테마 파일 밖에서 `Color(0x` 를 검색해 0건이어야 한다.

**R6. 작은 글자는 4.5:1, 큰 글자(18sp 이상, 굵으면 14sp 이상)와 아이콘, 경계선은 3:1 이상 대비를 낸다.** 나란히 놓인 버튼은 바탕색끼리 배경과 3:1 이상이다.
확인: 접근성 자동 검사의 대비 항목. 라이트와 다크 스크린샷 모두 Accessibility Scanner 로 본다.

**R7. 오류와 녹음 중 같은 의미 색은 동적 색에 맡기지 않는다.** 오류는 `error` 역할을 쓴다. 의미를 색 하나로만 전하지 않고 아이콘이나 문구를 함께 둔다.
확인: 동적 색을 켠 기기에서 배경화면을 빨강, 파랑으로 바꿔 녹음 중 표시와 오류가 구분되는지 본다.

**R8. 동적 색은 Android 12 이상에서만 켜고, 그 아래는 앱 고정 색 구성으로 돌아간다.** 라이트와 다크 고정 구성을 둘 다 둔다.
확인: Android 9 와 11 에뮬레이터에서 앱을 띄워 색이 기본 보라색이 아닌 앱 색인지 본다.

**R9. 라이트와 다크 둘 다 지원한다.** 라이트 전용 아이콘이나 이미지를 쓰지 않는다. 고도는 그림자보다 surface 역할 차이로 나타낸다.
확인: 화면마다 라이트, 다크 Roborazzi 스크린샷 두 장.

**R10. 구분선은 `outlineVariant`, 입력 칸 테두리처럼 경계를 알려야 하는 선은 `outline` 을 쓴다.**
확인: 코드 리뷰에서 `HorizontalDivider` 색을 본다.

### 레이아웃과 시스템 UI

**R11. 모든 화면을 edge-to-edge 로 그린다.** 끄는 화면을 두지 않는다. 모든 Android 버전에서 `enableEdgeToEdge()` 를 부른다. 배경은 시스템 바 밑까지 그리고, 누르는 요소와 글자는 `Scaffold` 의 `innerPadding` 이나 `WindowInsets.safeDrawing`(시스템 바, 디스플레이 컷아웃, 키보드) 만큼 안쪽에 둔다. 스크롤 콘텐츠는 시스템 바 아래까지 흐르게 하고 마지막 항목만 inset 만큼 띄운다. 제스처 내비게이션 바 위에 막을 덧대지 않고, 상태 바 보호막을 두 겹 쌓지 않는다.
확인: 제스처 내비게이션과 3버튼 내비게이션, display cutout 이 있는 에뮬레이터에서 Next 버튼과 탭 바 아이콘이 가려지지 않는지 본다.

**R12. Compact 폭에서 좌우 여백은 16dp 다.** 넓은 화면에서 본문 글자 폭은 한 줄 60자 안팎으로 제한하고 텍스트 필드와 카드를 화면 끝까지 늘리지 않는다.
확인: Compact 360dp 와 Expanded 폭 Roborazzi 스크린샷.

**R13. 회전, 폴더블 펼침, 창 크기 변경에서 입력값과 녹음 상태를 잃지 않는다.** 세로 고정에 기대지 않는다. targetSdk 36 에서는 큰 화면에서 무시된다.
확인: 키 입력 도중, 녹음 도중에 회전한다. 태블릿 에뮬레이터 가로 모드로 전 화면을 연다.

**R14. 뒤로가기는 `BackHandler` 나 `PredictiveBackHandler` 로만 가로챈다.** `onBackPressed` 재정의, `KEYCODE_BACK` 가로채기를 쓰지 않는다. 콜백은 필요한 동안만 `enabled = true` 로 둔다. 화면에 그린 뒤로가기 버튼이 시스템 뒤로가기를 대신하게 하지 않는다. `android:enableOnBackInvokedCallback="false"` 를 넣지 않는다.
확인: Android 16 에뮬레이터에서 각 화면을 뒤로 스와이프해 미리보기 애니메이션이 나오는지, 모의시험 중에만 확인 다이얼로그가 뜨는지 본다.

### 컴포넌트

**R15. 하단 탭은 내비게이션 바로 만들고 목적지 3~5개, 아이콘마다 1~2단어 라벨을 단다.** 라벨을 숨기거나 줄이지 않는다. 선택된 탭은 채운 아이콘, 나머지는 선 아이콘이다. 아이콘은 바 배경과 3:1 이상이다. 하위 화면(문항, 리포트 상세)에서는 탭 바를 숨긴다. Medium 이상 폭에서는 내비게이션 레일로 바꾼다.
확인: 내비게이션 바 스크린샷을 라이트, 다크, 글자 200% 로 찍는다. TalkBack 이 "홈, 탭, 3개 중 1번째" 처럼 읽는지 본다.

**R16. 한 화면에서 채운(filled) 버튼은 하나다.** 흐름을 끝내는 동작(동의 화면의 "동의하고 시작", 문항 화면의 녹음)에만 쓴다. 다음 단계로 가는 Next 는 tonal 버튼, 낮은 우선순위는 text 버튼이다. 버튼 글자는 1~3단어, 한 줄이다. 버튼 폭을 글자보다 좁게 고정하지 않는다.
확인: 화면별 스크린샷에서 filled 버튼 수를 센다.

**R17. 녹음, 재생, 다시 듣기처럼 묶인 버튼은 버튼 그룹으로 같은 크기와 모양으로 둔다.** 가장 중요한 동작만 더 크게 한다. 그룹은 한 줄을 넘겨 줄바꿈하지 않는다. 좁은 폭에서는 작은 버튼으로 줄인다.
확인: Compact 360dp, 글자 200% 스크린샷에서 그룹이 한 줄인지 본다.

**R18. 기다림 표시는 시간으로 고른다.** 200ms 미만은 아무것도 안 띄운다. 200ms~5초는 로딩 인디케이터(기본 48dp, 24~240dp), 5초 넘게 걸리고 진행률을 알면 진행 표시(progress indicator)를 쓴다. 로딩 인디케이터를 진행 표시로 바꿔 끼우지 않는다. 한 작업은 앱 전체에서 같은 종류의 표시를 쓴다.
확인: 리포트 생성과 업로드 시간을 재서 어느 표시를 쓸지 정했는지 본다. 네트워크 지연 시뮬레이션에서 확인한다.

**R19. 다이얼로그는 꼭 끊어야 할 때만 쓰고 동작 버튼은 두 개까지다.** 제목은 "확실합니까?" 같은 모호한 질문이나 사과로 쓰지 않는다. 확인 버튼은 "확인" 대신 "그만두기" 처럼 결과를 적고, 취소는 확인 버튼 왼쪽에 둔다. 덜 중요한 알림은 스낵바로 보낸다.
확인: 다이얼로그 문구를 리뷰한다. 버튼 수와 순서를 스크린샷으로 본다.

**R20. 스낵바는 한 번에 하나, 아이콘 없이 짧은 문장과 text 버튼 최대 하나다.** 하단 탭 바와 FAB 를 가리지 않는다. 스낵바에만 있는 기능을 만들지 않는다.
확인: 탭 화면에서 스낵바를 띄운 스크린샷.

**R21. 설정의 스위치는 누르는 즉시 적용되는 켜기/끄기에만 쓰고 항상 왼쪽에 라벨을 둔다.** 저장 버튼이 필요한 선택은 체크박스, 하나만 고르는 선택은 라디오 버튼이다. 스위치와 라벨을 한 행으로 묶어 행 전체가 눌리게 한다(`toggleable(role = Role.Switch)`).
확인: TalkBack 이 "알림, 스위치, 켜짐" 처럼 라벨과 상태를 한 번에 읽는지 본다.

**R22. 키 입력 칸은 항상 보이는 라벨을 단다.** 플레이스홀더로 라벨을 대신하지 않는다. 오류는 칸 바로 아래에 어떻게 고치는지 적고, 보조 문구와 오류 문구를 동시에 띄우지 않는다. 키처럼 긴 값은 한 줄 필드를 쓴다.
확인: 오류 상태 스크린샷. TalkBack 이 라벨과 오류 문구를 읽는지 본다.

### 접근성 의미 정보

**R23. 글자 없는 아이콘 버튼에는 동작을 적은 설명을 단다.** "재생 버튼" 이 아니라 "재생" 으로, 역할 이름을 넣지 않는다. 같은 아이콘이 반복되면 대상을 넣어 서로 다르게 한다("1번 문항 다시 듣기"). 장식 이미지는 `contentDescription = null` 이다. 상태가 바뀌는 버튼(녹음, 녹음 중지)은 설명도 상태에 맞게 바꾼다.
확인: 접근성 자동 검사의 라벨 누락 항목. TalkBack 으로 문항 화면을 한 바퀴 돈다.

**R24. 화면 제목은 `semantics { heading() }` 으로 표시하고, 카드처럼 한 덩어리인 요소는 한 번에 읽히게 묶는다.** 리포트 점수 카드는 "발음 점수 82점" 처럼 한 번에 읽혀야 한다. 스와이프로만 할 수 있는 동작은 버튼이나 접근성 동작으로도 할 수 있게 한다.
확인: TalkBack 제목 단위 이동으로 화면 사이를 옮겨 본다. 접근성 자동 검사의 읽는 순서 항목.

**R25. 모션은 테마의 모션 토큰을 쓴다.** 위치와 크기는 spatial, 색과 투명도는 effects 용수철이다. 작은 요소는 fast 속도다. 화면 코드에 `tween(300)` 같은 시간 값을 직접 쓰지 않는다.
확인: 테마 밖에서 `tween(` 과 `spring(` 를 검색한다.

## 5. 아직 확인하지 못한 것

- 예측 뒤로가기 앱 안 애니메이션의 세부 수치(축소 비율, 여백, 시간)
- Android 9~13 의 글자 크기 최대 배율. 200% 는 Android 14 부터다
- 스낵바 표시 시간
- Compose Multiplatform 공통 코드에서 동적 색, `enableEdgeToEdge`, `BackHandler` 에 대응하는 API 이름과 판. 지금은 androidMain 에 둔다고 보고 썼다
