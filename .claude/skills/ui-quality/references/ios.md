# iOS 규칙

대상은 iOS 18 과 iOS 26 이다. 터치 영역 44pt, 본문 17pt(최소 11pt), 글자 대비 4.5:1, 가장 큰 접근성 글자(AX5, 본문 53pt)까지 버텨야 한다.

## 1. 누가 무엇을 그리나

iOS 화면에는 시스템이 그리는 부분과 Compose 가 그리는 부분이 섞인다. 둘은 접근성 설정을 따르는 방식이 다르다.

| 영역 | 그리는 쪽 | 시스템 설정(글자 크기, 다크 모드, 투명도 줄이기, 동작 줄이기, 대비 높이기) |
|---|---|---|
| 시트, 알림창, 액션 시트 | 시스템 컴포넌트 | 시스템이 알아서 따른다. iOS 26 에서는 Liquid Glass 도 시스템이 입힌다 |
| 하단 탭 | 아직 정하지 않았다(시스템 탭 바 또는 Compose) | 시스템 탭 바면 시스템이 따른다. Compose 로 그리면 아래 Compose 규칙을 모두 지킨다 |
| 그 밖의 화면(시작, 키 입력, 동의, 홈, 기록, 설정, 모의시험 문항, 리포트) | Compose | 저절로 따르지 않는다. 설정 값을 직접 읽어 반영한다 |

이 문서 규칙의 절반이 Compose 화면에 걸리는 이유가 이것이다. 탭 바 규칙(iOS-14, 15)은 시스템 탭 바를 쓸 때 기준이다.

## 2. 규칙

확인할 때 쓰는 설정 위치는 다음과 같다. 시뮬레이터와 실기기 모두 같은 경로다.

- 큰 글자: 설정 > 손쉬운 사용 > 디스플레이 및 텍스트 크기 > 더 큰 텍스트 (더 큰 접근성 크기 켜고 슬라이더 끝까지)
- 대비 높이기, 투명도 줄이기: 설정 > 손쉬운 사용 > 디스플레이 및 텍스트 크기
- 동작 줄이기: 설정 > 손쉬운 사용 > 동작
- 다크 모드: 설정 > 디스플레이 및 밝기
- 빠른 전환: Xcode 실행 중 디버그 바의 Environment Overrides 에서 글자 크기, 외관, 접근성 항목을 바꾼다. Accessibility Inspector 로 라벨과 대비를 검사한다

### 크기와 배치

**iOS-01 터치 영역은 44x44pt 이상.** 아이콘이 작아도 누르는 영역은 44pt 를 준다. 공통 코드가 48dp 를 쓰면 그대로 둔다. 28pt 미만은 어떤 경우에도 안 된다. Compose 의 dp 가 iOS 에서 pt 와 같은 크기로 그려진다고 보고 쓰는데, 이 대응은 원문으로 확인하지 못했으니 Accessibility Inspector 로 실제 프레임 크기를 한 번 잰다.
확인: Accessibility Inspector 로 녹음, 재생, 다시 듣기, Next 의 프레임 크기를 잰다.

**iOS-02 누를 수 있는 요소 사이 간격.** 배경이나 테두리가 있는 버튼 둘레 약 12pt, 테두리 없는 아이콘 버튼은 보이는 가장자리 둘레 약 24pt 를 둔다.
확인: 모의시험 문항 화면 스크린샷에서 아이콘 간격을 잰다.

**iOS-03 Compose 화면도 edge-to-edge 로 그린다.** 배경과 스크롤 콘텐츠는 안전 영역 밖까지 그리고, 글자와 버튼은 `WindowInsets.safeDrawing` 으로 안전 영역 안에 둔다. Android 와 같은 방식으로 맞춰 두 플랫폼 화면 코드를 하나로 유지한다. 키보드가 올라오는 화면은 `imePadding` 을 줘서 입력칸과 확인 버튼이 키보드에 가리지 않게 한다.
확인: Dynamic Island 기기와 홈 버튼 기기(iPhone SE) 시뮬레이터에서 키 입력, 모의시험 문항 화면을 연다. 키보드를 띄운 상태도 본다.

**iOS-04 탭 바 밑까지 스크롤되는 목록은 마지막 항목이 탭 바에 가리지 않는다.** 목록 아래 여백을 하단 inset 만큼 준다.
확인: 기록, 설정 탭 목록을 끝까지 스크롤한다. iOS 18 과 iOS 26 둘 다 본다.

**iOS-05 주요 동작 버튼은 화면 폭 버튼으로, 나란한 버튼은 높이를 같게.** 우선 선택지는 크기 말고 스타일(채움 대 테두리)로 구분한다.
확인: 시작 분기 화면, 모의시험 Next, 동의 화면 버튼.

### 글자

**iOS-06 글자 크기는 시스템 글자 크기 설정을 따른다.** Compose 에서 글자는 `sp` 로 쓰고 `dp` 고정이나 `fontScale` 을 1 로 덮어쓰지 않는다. 본문 기본 17pt, 어떤 글자도 11pt 미만으로 두지 않는다. 앱 실행 중 글자 크기를 바꿨을 때 바로 반영되는지는 Compose Multiplatform 판에 따라 다를 수 있어 직접 확인한다.
확인: 앱을 띄운 채 Environment Overrides 로 글자 크기를 xSmall 과 AX5 로 바꾼다. 앱을 다시 시작해서도 본다.

**iOS-07 가장 큰 접근성 글자(AX5, 본문 53pt)에서도 화면이 쓸 수 있어야 한다.** 가로 배치는 세로로 쌓고, 고정 높이 행은 늘어나게 하고, 스크롤 영역 안 글자는 자르지 않는다. 탭 라벨처럼 모든 글자를 키울 필요는 없지만 본문과 문항 글자는 커져야 한다.
확인: AX5 에서 리포트, 모의시험 문항, 설정을 스크린샷으로 남긴다. 잘림, 겹침, 버튼이 화면 밖으로 밀려난 곳이 0개여야 한다.

**iOS-08 가는 굵기를 쓰지 않는다.** Regular 미만(Light, Thin, Ultralight)은 본문과 버튼에 쓰지 않는다. 커스텀 글꼴을 쓰면 굵은 텍스트 설정에도 반응하게 한다.
확인: 굵은 텍스트 설정을 켜고 Compose 화면 글자가 굵어지는지 본다.

### 색과 모드

**iOS-09 대비는 17pt 이하 4.5:1, 18pt 이상이나 굵은 글자 3:1 이상.** 직접 정한 전경색과 배경색은 작은 글자에서 7:1 을 목표로 한다. 라이트와 다크 둘 다 잰다.
확인: Accessibility Inspector 의 Audit, 또는 대비 계산기로 테마 색 쌍을 모두 잰다.

**iOS-10 색 값을 화면 코드에 박지 않는다.** 용도별 색 토큰(주 텍스트, 보조 텍스트, 배경, 올라온 배경, 구분선, 강조, 경고)을 라이트, 다크, 고대비 라이트, 고대비 다크 4벌로 정의하고 화면은 토큰만 쓴다. iOS 에서 대비 높이기가 켜지면 고대비 벌로 바꾼다.
확인: 대비 높이기를 켜고 끄며 홈, 리포트 화면 색이 바뀌는지 본다.

**iOS-11 다크 모드는 시스템 설정을 따르고, 앱 안에 라이트/다크 선택 설정을 두지 않는다.** 시트와 모달 위 배경은 기본 배경보다 한 단계 밝은 색을 쓴다.
확인: 앱 실행 중 다크 모드를 바꿔 모든 화면이 바로 따라오는지 본다. 다크 모드와 대비 높이기, 투명도 줄이기를 함께 켠 상태도 본다.

**iOS-12 색만으로 상태를 알리지 않는다.** 녹음 중, 정답과 오답, 점수 구간은 글자나 아이콘을 같이 쓴다.
확인: 손쉬운 사용 > 디스플레이 및 텍스트 크기 > 색상 필터의 흑백으로 보고도 상태가 구분되는지 본다.

### Liquid Glass 와 시스템 컴포넌트

**iOS-13 Compose 로 그리는 본문에 유리 효과를 흉내 내지 않는다.** 반투명 블러 카드, 떠 있는 유리 버튼을 Compose 로 만들지 않는다. 콘텐츠 영역 구분은 불투명 배경이나 일반 반투명 재질 수준으로 한다. 유리 위에 유리를 겹치지 않는다.
확인: iOS 26 에서 홈, 리포트 스크린샷에 탭 바 말고 유리처럼 보이는 요소가 없는지 본다.

**iOS-14 탭 바, 시트, 알림창에 커스텀 배경색과 커스텀 그림을 넣지 않는다.** 시스템 기본 외관을 쓴다. 탭 바 강조색은 콘텐츠 배경과 비슷한 색을 피한다. 화면 전용 버튼을 탭 바 부속 영역에 넣지 않는다.
확인: iOS 18 과 iOS 26 에서 각각 탭 바, 시트, 알림창 스크린샷을 남겨 시스템 앱(설정, 메모)과 비교한다.

**iOS-15 탭은 항상 3개 그대로 보인다.** 내용이 없어도 탭을 숨기거나 비활성화하지 않는다. 라벨은 한 단어(홈, 기록, 설정), 아이콘은 채워진 SF Symbols 를 쓴다. 탭 바는 모달(모의시험 전체 화면 등)이 덮을 때만 사라진다.
확인: 기록이 0건인 새 설치 상태에서 기록 탭을 연다. 빈 화면 안내와 다음 할 일 버튼이 있어야 한다.

**iOS-16 iOS 26 에서 유리를 끄는 호환 설정(`UIDesignRequiresCompatibility`)을 쓰지 않는다.**
확인: Info.plist 에 키가 없는지 본다.

### 이동과 모달

**iOS-17 Compose 로 들어간 하위 화면에는 왼쪽 위 뒤로 버튼과 왼쪽 가장자리 스와이프 둘 다 있어야 한다.** 뒤로 버튼은 표준 기호(chevron)만 쓰고 "뒤로" 글자를 붙이지 않는다. 가로 스크롤 요소가 화면 왼쪽 끝에 붙어 스와이프와 겹치지 않게 한다.
확인: 설정 하위 화면, 리포트 상세에서 버튼과 스와이프로 각각 돌아가 본다. VoiceOver 켠 상태에서 뒤로 버튼이 첫 요소 근처에서 읽히는지 본다.

**iOS-18 화면 제목은 15자 미만, 앱 이름을 제목으로 쓰지 않는다.**
확인: 모든 화면 제목 글자 수를 센다.

**iOS-19 시트는 한 번에 하나, 아래로 쓸어 닫을 수 있게, 취소는 왼쪽 위 완료는 오른쪽 위.** 완료 버튼만 두지 않는다. 입력한 내용이 있는데 쓸어 닫으면 액션 시트로 저장 여부를 묻는다. 높이 조절 시트에는 손잡이를 둔다.
확인: 각 시트를 쓸어 닫아 본다. 입력 중일 때 확인이 뜨는지 본다.

**iOS-20 알림창은 되돌릴 수 없는 예상 밖 손실과 꼭 결정이 필요할 때만.** 버튼 3개 이하, 제목 두 줄 이하, 버튼은 동사(그만두기, 삭제), 취소 버튼은 "취소", 사용자가 고르지 않은 파괴적 동작은 빨간 스타일. 앱 시작 때 알림창을 띄우지 않는다. 정보만 주는 상황은 화면 안 문구로 보여 준다.
확인: 앱에서 알림창이 뜨는 경우를 모두 나열해 이 조건에 맞는지 대조한다. 키 만료, 네트워크 없음은 알림창이 아니어야 한다.

### 접근성 동작

**iOS-21 동작 줄이기가 켜지면 Compose 애니메이션을 줄인다.** 좌우 슬라이드 전환은 페이드로, 확대와 반동은 끄고, 파형처럼 계속 움직이는 애니메이션은 정지된 표시로 바꾼다. 애니메이션이 끝날 때까지 입력을 막지 않는다. iOS 에서는 `UIAccessibilityIsReduceMotionEnabled` 값을 읽어 공통 코드로 넘긴다.
확인: 동작 줄이기를 켜고 모의시험 한 회를 끝까지 진행한다.

**iOS-22 투명도 줄이기가 켜지면 Compose 의 반투명과 블러를 불투명으로 바꾼다.** iOS 에서는 `UIAccessibilityIsReduceTransparencyEnabled` 값을 읽는다.
확인: 투명도 줄이기를 켜고 iOS 26 에서 탭 바 밑으로 목록을 스크롤해 글자가 읽히는지 본다.

**iOS-23 VoiceOver 로 모든 화면을 끝까지 쓸 수 있어야 한다.** 직접 그린 버튼과 그래프에 라벨을 달고, 장식 이미지는 숨기고, 화면 제목과 절 제목에 heading 을 단다. 녹음 버튼 라벨은 상태에 따라 바뀌고, 녹음 시작과 끝, 자동 정지는 소리로 알린다. 시간이 지나면 자동으로 사라지는 안내를 쓰지 않는다.
확인: VoiceOver 를 켜고 시작 분기부터 키 입력, 동의, 모의시험 1문항, 리포트까지 화면을 보지 않고 진행한다. 라벨 없는 요소("버튼", "이미지"로만 읽히는 것)는 0개여야 한다.

### 입력, 권한, 녹음

**iOS-24 키 입력칸은 비밀 입력칸으로, 라벨과 예시를 두고, 붙여넣기를 막지 않는다.** 값은 키체인에 저장하고 입력칸을 미리 채우지 않는다. 형식 오류는 입력칸 바로 아래에 고치는 방법으로 쓴다.
확인: 키 붙여넣기, 잘못된 형식 입력, 앱 재시작 후 다시 들어가기.

**iOS-25 마이크 권한은 처음 녹음 버튼을 누를 때 묻고, 녹음 중 표시를 화면 안에 둔다.** 앞에 안내 화면을 둔다면 버튼은 "계속" 하나만 둔다. 권한 설명 문구에 녹음을 무엇에 쓰는지(분석하려고 Gemini 로 보낸다는 것 포함) 빠짐없이 적는다. 거부한 사용자에게는 문항 화면 안에서 설정 열기 방법을 보여 준다. 녹음 중에는 빨간 점, "녹음 중" 글자, 경과 시간을 같이 보여 주고, 전화 같은 중단이 오면 녹음을 멈추고 상태를 보여 준다. 앱 안에서 개인정보 처리방침 링크를 찾을 수 있게 설정에 둔다.
확인: 새 설치에서 권한 허용과 거부를 각각 진행한다. 녹음 중 시뮬레이터 전화 수신이나 다른 앱 오디오 재생으로 중단을 만들어 본다. 무음 스위치를 켜고도 재생이 들리는지 본다.


## 3. 아직 확인하지 못한 것

규칙을 쓸 때 직접 확인하지 못한 것이다. 화면을 만들면서 확인되면 해당 규칙을 고친다.

- Compose 의 dp 가 iOS 에서 pt 와 같은 크기로 그려지는지. iOS-01 은 같다고 보고 썼다
- Compose 화면이 앱 실행 중 Dynamic Type 변경을 바로 반영하는지
- Compose 가 iOS 동작 줄이기, 투명도 줄이기 설정을 스스로 읽는지. 지금은 직접 읽는다고 보고 iOS-21, 22 를 썼다
- 우리 내비게이션 라이브러리 판에서 왼쪽 가장자리 스와이프 뒤로가기가 동작하는지
- Compose 로 그린 스크롤 영역에 iOS 26 스크롤 가장자리 효과와 탭 바 축소가 걸리는지
